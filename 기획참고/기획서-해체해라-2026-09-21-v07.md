> 진지한 야구, 이상한 선수들. 잘 키운 선수를 유지하고 구단을 운영하면서, 경기에서는 “아놔…”와 “이번에는 이기고 만다”를 경험하는 PC 중심 픽셀 야구 게임.

작성일: 2026-09-21  
문서 버전: **PRD v07**  
기획: 사용자 / 정리: Codex  
문서 상태: **2026-09-21까지의 결정을 통합. 공격·수비 버튼 지시, 작은 전신 도트 캐릭터와 경기 시점 동작, Neo둥근모/갈무리9 역할 분담을 반영. 경영 수치·동작 완성도는 미정/검증 대기로 구분.**

- 기존 PRD v01~v06와 게임 파일은 보존한다. 이 문서는 PRD v06를 대체하는 최신 기획 기준이며, 변경분만 덧붙인 문서가 아니다.

- 글꼴을 먼저 넣었던 `versions/v07/index.html`과 `previews/motion-atlas-2026-09-21-v02/index.html`은 **적용 보류된 비교 사본**이다. 같은 v07 번호를 이유로 승인된 최신 게임으로 취급하지 않는다.
- 최신 사용자 결정이 앞선 결정을 대체한다. 폐기된 15명/25명 한도, 초기 9명, 승리 영입 선택은 새 규칙으로 사용하지 않는다.

- 원래 야구 규칙을 기본으로 삼고, 이 문서에 명시한 5이닝·최대 7회 등의 게임 예외를 적용한다. 시안의 숫자·이름·선수 수·버튼은 규칙의 근거가 아니다.
- 2026-09-11 이전의 별도 야구 게임과 잘못 이어진 사이트는 근거에서 제외한다. 이번 프로젝트의 PRD v05 이후 사용자 피드백과 그에 따른 게임 v01~v06 변경 기록은 연속된 작업 자료로 사용한다.

## 1. 풀고자 하는 문제

- 직접 조작을 늘린 미리보기보다 버튼 지시가 편하다는 사용자 결정을 따른다. 버튼 수나 미니게임을 늘리기보다 선수의 개성·읽기 쉬운 움직임·결과 연출로 보는 재미를 높인다.
- 선수의 성장만 누적되면 강한 선수 9명을 계속 사용하고 난이도가 낮아질 수 있다. 영입·연봉·시설·훈련에 같은 자금을 사용해 운영 선택을 만든다.
- 체력이 떨어진 선수를 교체해 후보 선수도 활용하게 한다. 새 경기에서는 모두 회복하므로 경기 간 강제 휴식 제도와는 구분한다.
- 실패 원인을 이해할 수 있어야 한다. 조작이 불편하거나 결과가 너무 빨리 사라져 생기는 답답함보다, 선수의 황당한 판단과 상황에 맞는 놀림에서 재미를 만든다.
- 기존의 선수 수집·육성·야구 규칙·본헤드·재도전 정체성을 유지한다. MLB 판매와 장기 업적은 마지막 미래 계획에 둔다.

## 2. 사용자

- 야구의 기본 지식이 있는 사용자. PC 브라우저에서 플레이한다.
- 직접 경기 개입, 자동 경기, 경기 스킵을 상황에 맞게 사용한다.
- 한 경기의 시간을 고정하지 않는다. 공의 수와 경기 내용에 따라 달라진다.
- 휴대폰 최적화와 창을 내렸을 때의 소형 경기 패널은 추후 계획이다.

## 4. 핵심 기능

| 묶음 | 사용자 경험 |
|---|---|
| 선수 운영 | 초기 12명을 확인하고 35명까지 영입, 9명 편성, 전체 능력치와 기록 확인, 경기 중 교체 |
| 구단 경영 | 하나의 자금으로 연봉·영입·훈련·시설을 선택하고, 입장권·매장·경기 수입을 관리 |
| 관계와 성장 | 선수 애정도·개인 팬·사건을 살피고, 관련 시설을 통해 능력치와 스태미나 성장 |
| 야구 경기와 연출 | 규칙에 맞는 반자동/자동 경기, 공격 A·수비 B, 본헤드·리액션, 버튼 지시·개성 있는 선수 동작과 낙구 안내 |
| 기록과 이어하기 | 경기 스킵 후 요약, 개인·팀 기록, 저장 2칸·복구·백업 |

흐름: 저장 선택 → 팀 생성 → 초기 선수 12명 이름·등번호 확인 → 9명 타순·수비 편성 → 시설·영입 등 운영 → 경기 → 결과·자금·팬/관계 변화 확인 → 훈련·시설·계약·편성 → 다음 경기.

- 초기 선수는 새 팀 생성 때만 지급한다. 다음 경기에서 선수단을 다시 뽑지 않는다.
- 시설을 먼저 짓지 않았다는 이유만으로 경기 시작을 막는 규칙은 정하지 않았다. 시설은 관련 훈련을 여는 조건이다.
- 게임 내부 자동 판단은 외부 생성형 AI 호출이 아닌 자체 경기 로직이다.
- Codex는 추후 요청 시 구현과 검증을 담당한다. 사용자는 경기의 조작감·속도·가독성·난이도·재도전 재미를 확인한다.

### 5-2. 눈으로 확인할 완료 조건

1. 새 팀에 12명이 생성되고, 시설은 0개·건물 한도는 5개이며 시작 자금이 지급된다. 확정한 비용표 기준 시설 2~3개부터 시작할 수 있다.
2. 9개의 서로 다른 선수·타순·포지션을 모두 지정하기 전에는 경기 시작을 막는다. 선수 이름·번호·외형을 구분할 수 있다.
3. 자금 영입은 비용과 인원을 한 번만 반영하며 35명을 넘지 않는다. 승리로 별도의 무료 영입 선택을 강제하지 않는다.
4. 해당 훈련시설이 없으면 관련 훈련을 할 수 없다. 시설이 있어도 자금 부족·성장 한도이면 차감하지 않는다.
5. 스태미나 능력치와 남은 체력을 구분하고, 일반 스윙도 체력을 사용한다. 다음 새 경기에서 전부 회복하되 같은 경기 복구로 회복하지 않는다.
6. 피로로 낮아진 능력은 해당 경기의 적용값이며 영구 성장값을 덮어쓰지 않는다. 체력이 낮아도 강제로 출전 불가 처리하지 않는다.
7. 공격 A·수비 B가 명확히 다르고, 수비 지시판 위/아래·좌/우가 그라운드 방향과 일치한다.

### A-1. 초기 선수와 영입 선수

- **초기 12명, 보유 최대 35명, 경기 출전 9명.** 기존 15명 또는 중간 제안 25명은 더 이상 적용하지 않는다.

- 기존 9개 능력치의 초기 생성 규칙을 유지한다. 서로 다른 강점 1개와 약점 1개를 뽑고 나머지 7개를 생성한다.

| 기존 9개 능력치의 초기 구분 | 범위 |
|---|---|
| 야구센스가 강점 | 60~70 |
| 다른 능력이 강점 | 75~100 |
| 약점 1개 | 1~25 |
| 나머지 7개 | 각각 20~55 |

- 신규 영입 후보의 기존 능력치는 야구센스 1~70, 다른 8개 각각 1~100 정수를 독립적으로 같은 확률로 생성하는 기존 규칙을 유지한다. 가격과 능력치 관계는 별도 미정이다.

- 포지션별 능력 보정이나 강한 투수 지급 보장은 기존에 정하지 않았다. 초기 12명에서 후보 역할까지 보장할지도 미정이다.

- 좌타/우타, 당겨치기/중앙/밀어치기 성향은 무작위다. 홈에서 외야를 보는 좌우 기준을 유지한다. 우타 당겨치기는 좌측, 좌타 당겨치기는 우측이며 성향은 확정 타구 방향이 아니다.

### A-3. 스태미나와 피로 — 확정 방향

| 용어 | 뜻 |
|---|---|
| 스태미나 능력치 | 무작위로 받고 훈련으로 키우는 선수 능력 |
| 경기 중 남은 체력 | 현재 경기에서 실제로 남은 양 |
| 성장 한도 | 스태미나 능력치를 훈련으로 올릴 수 있는 공통 한계. 숫자 미정 |

- 설명 예시: 스태미나 능력치가 60이면 새 경기 60/60, 체력 20 사용 후 40/60. 능력치가 65로 성장하면 이후 새 경기 65/65. 60·65는 확정 범위가 아니다.
- 투구 수 증가, **일반 스윙과 풀스윙**, 시프트 실패 등으로 멀리 달리는 수비 행동에 따라 체력이 소모된다.
- 행동별 소모량과 풀스윙/일반 스윙의 차이, 주루·벤치·공수 교대 중의 소모/회복 세부는 미정이다. 행동별 소모와 난이도를 조정한 뒤 성장 한도를 결정한다.
- 강도 지시만 했고 실제 스윙은 없었다면 스윙 소모로 처리하지 않는 연결안을 따른다. 수비 이동량과 소모를 연결하는 계산은 미정이다.
- **새 경기가 시작될 때 모든 선수의 남은 체력이 각자 스태미나 능력치까지 전부 회복된다.** 같은 경기 불러오기·재개·공수 교대·스킵을 새 경기로 오인해 회복하지 않는다.
- 낮은 체력은 경기 출전 금지가 아니다. **그 경기에서만 능력이 대폭 감소**하며 원래 성장한 능력치는 보존한다.
- 어느 체력 수준부터 어떤 능력이 얼마나 낮아지는지, 0 이하 방지와 최저 적용값은 미정이다. 시안의 색상·비율을 규칙으로 확정하지 않는다.
- 야구센스 70%의 기존 본헤드 능력 비중은 유지하되, 피로로 감소한 값을 본헤드 계산에도 사용할지는 미정이다.

### A-4. 편성과 경기 중 교체

- 출전 포지션은 P·C·1B·2B·3B·SS·LF·CF·RF, 타순은 1~9번이다. 고정 선수 포지션·DH는 추가하지 않는다.
- 빈 타순 칸 선택 → 보유 선수 지정 → 수비 위치 배정의 방식. 같은 선수를 두 칸에 넣지 않는다.
- 편성 화면에서 기존 9개 능력치와 스태미나를 모두 확인한다. 세부 경기 기록은 선수 선택으로 연다.
- 최초 편성은 빈 9칸에서 시작하고, 기존 팀은 저장된 편성을 이어간다. 미완성 초안을 완성 출전 명단과 구분해 저장한다.
- **경기 중 교체를 추가한다.** 피로한 선수와 후보의 능력·체력을 비교할 수 있어야 한다.
- 교체 가능 시점, 투수/야수/대타·대주자 지원 범위, 교체 후 재출전, 수비 위치 변경, 경기 등록 인원 제한은 미정이다. 35명 보유 한도를 별도 등록 한도로 오해하지 않는다.
- 교체 후에도 이미 발생한 기록은 해당 선수에게 남고, 팀의 타순·아웃·주자·점수를 임의로 초기화하지 않는다. 책임 실점·상속 주자 등 세부 기록 처리는 구현 전 검증한다.
- 경기 밖의 영입·방출로 편성 선수가 바뀌면 새 선수가 기존 포지션·타순을 우선 이어받는 기존 편의 규칙을 유지한다. 경기 중 교체 규칙과 혼용하지 않는다.

### A-5. 개인 기록

- 타격: 경기·타석·타수·안타·2루타·3루타·홈런·볼넷·사구·희생플라이·삼진·타점·득점.
- 투구: 등판·아웃 수에 대응하는 투구 이닝·실점·탈삼진·볼넷·폭투. 수비: 실책·포일·본헤드. 병살·헛스윙·최근 무안타도 실제 사건과 연결한다.
- 타율=안타/타수, 출루율=(안타+볼넷+사구)/(타수+볼넷+사구+희생플라이), 장타율=총루타/타수. 분모가 없으면 ‘—’, 실제 횟수 0은 0으로 구분한다.
- 사구·희생플라이는 타석에 포함하되 타수에는 포함하지 않는다. 폭투는 투수, 포일은 포수 기록으로 구분하며 그 자체를 실책 개수에 추가하지 않는다.
- 최근 무안타는 마지막 안타 이후 연속 무안타 **타수**. 0~5타수에는 멘트 없음, **6타수 이상부터 표시**. 볼넷·사구·희생플라이는 늘리지도 끊지도 않고, 안타면 0으로 초기화. 경기 종료나 재접속으로 끊지 않는다.
- 개인 기록은 사용자에게 공개한다. 선수 관리에서 전체 누적 기록, 라인업에서 타율·출루율/투구 이닝·볼넷/실책·본헤드 등 역할별 요약과 상세 보기를 제공한다.
- 기록 표본인 경기 수·타석 수 등을 함께 보여준다. 이적·방출 시 기록의 보존/삭제 정책은 기존 안내와 새 계약 시스템의 연결을 부록 I에서 정한다.

## 부록 B. 구단 자금·영입·연봉·애정도·팬

### B-1. 자금과 보상

- 재화는 **구단 자금 하나**로 통합한다. 훈련 코인과 운영 돈을 별도로 만들지 않는다.
- 사용처: 영입, 연봉, 훈련, 시설 건설·유지, 경기장 업그레이드.
- 수입 방향: 경기 보상, 홈 경기 입장권, 매장 판매. 승리 때는 영입 기회 대신 자금을 지급한다.
- **승리마다 무료 영입/거절 15코인 중 하나를 고르고 다음 경기로 가던 흐름은 대체한다.** 영입을 거절해 돈을 받거나 승리 후 미선택 상태로 다음 경기를 막는 규칙을 새 자금 영입에 그대로 적용하지 않는다.
- 트로피는 **누적 승리 수 자체를 표시**한다. 영입·훈련에 소비하지 않고 패배·무승부로 증가하지 않는다. 후속 업적이 생겨도 트로피를 지급해 승리 수를 늘리지 않는다.
- v05의 ‘경기 기본 1+우리 득점 코인’은 구 경제의 기준이다. 새 자금 단위에서의 유지/환산·승리 보너스 합산 여부·패배/무승부 보상은 **재설계 미정**이다. 아무 확인 없이 같은 숫자를 돈으로 바꾸지 않는다.
- 같은 경기의 수입·비용·승리 기록은 한 번만 반영한다. 정산 주기, 홈/원정 수입 차이, 적자·연봉 미지급 처리는 미정이다.

### B-2. 자금 영입과 한도

- 영입할 선수의 능력치·스태미나·필요 자금을 확인하고 사용자가 영입을 결정한다.
- **보유 한도 35명**. 정원·자금 부족이면 이유를 표시하고 자동 방출 또는 비용만 차감하지 않는다.
- 선수 후보 수, 후보 갱신 시점, 영입료 산정, 선수의 초기 팬·애정도·연봉 조건은 미정이다.
- 한도가 찼을 때 기존 선수를 내보내고 새 선수를 영입하는 동선을 유지하는 방향이나, 새 계약 제도의 방출 비용·판매 대가·기록 보존을 결정해야 한다.
- 기존 선수 삭제에는 대상과 기록 영향을 알리는 확인이 필요하다. 구매와 방출이 중간 실패할 때 선수·자금이 일부만 바뀌지 않도록 검증한다.

### B-3. 연봉과 구단 애정도

- 성장한 좋은 선수를 유지하는 데 자금이 들도록 연봉을 도입한다. **총연봉 상한 제도를 확정한 것은 아니다.**
- 애정도는 선수가 구단을 좋아하고 남고 싶어 하는 정도다. 복지시설과 사건·협상에 영향을 받는다.
- 높은 애정도는 연봉 할인 협상에 도움이 되는 방향. 지나치게 낮은 연봉 제안은 애정도 하락과 불만을 만들 수 있다.
- 불만이나 사건에 따른 이적 요구·재계약 거절·타 구단 이적을 구상한다. 자동 이탈 확률이나 즉시 사라지는 규칙은 미정이다.
- **제안:** 계약 기간에는 연봉을 유지하고 재계약 때 성장한 몸값을 반영한다. 사전 불만 신호를 보여주고 사용자가 대응할 여지를 둔다.
- 계약 기간·지급 주기·연봉 산식·협상 횟수·할인 한도·애정도 범위·회복 속도·퇴단 처리는 미정. ‘10경기 계약’은 설명용 제안이지 확정값이 아니다.

### B-4. 개인 팬·관중·입장료

- 개인 팬 수와 선수 능력·구단 애정도를 분리한다. 실력은 평범하지만 인기 있는 선수, 잘하지만 팬이 떠나는 선수가 가능하다.
- 선수별 팬을 참고해 다음 경기의 예상 관중을 보여주고 사용자가 입장료를 조절하는 방향이다.
- **제안:** 선수 팬의 중복, 출전 여부, 입장료, 관람 의향, 좌석 수를 반영해 실제 관중을 계산한다. 개인 팬 수 합계를 그대로 관중 수로 사용하지 않는다.
- 입장권·음식점·굿즈 등 수입과 연결하되, 팬 증가가 반드시 같은 수의 입장객 증가를 뜻하지 않는다.
- 관중 계산식·표 값 범위·홈/원정 정책·좌석 수·별도 구단 팬 수치 도입 여부는 미정이다.

### B-5. 선수 행동과 팬 변화 이벤트

| 분류 | 후보 사례 | 방향 |
|---|---|---|
| 경기 활약 | 끝내기 안타·역전 홈런·결정적 호수비·꾸준한 성적 | 팬 증가 |
| 팬 서비스 | 사인회·어린이 팬과 약속 지키기·원정 팬 감사 인사 | 팬 증가 |
| 선행 | 개인 기부·유소년 지도·청소·봉사 | 팬 증가 |
| 팬 실망 | 팬 무시·행사 무단 불참·팬 탓 인터뷰 | 팬 감소 |
| 생활 속 사고 | 쓰레기 버리기·새치기·팬 선물 방치 | 팬 감소 |
| 사건 이후 | 사과·후속 선행 또는 변명·추가 논란 | 일부 회복 또는 추가 감소 |

- 팬 수가 행동과 활약에 따라 변하는 방향은 확정. 위 개별 사건은 후보이며 발생 빈도·변화량·대응 선택지는 미정이다.
- 경기 사건은 실제 기록에서 발생시킨다. 일어나지 않은 끝내기나 홈런을 기사로 만들지 않는다.
- 본헤드마다 팬을 자동 차감하지 않는다. 경기 실패와 팬 손실이 항상 이중으로 발생하지 않도록 설계한다.
- 선수 개인 기부를 구단 돈에서 몰래 차감하지 않는다. 구단 후원은 비용과 선택을 명시하는 별도 처리다.
- 사건 선수·내용·팬 수 변화와 영향을 확인할 수 있게 한다. 경기 중 한 사건 한 리액션 규칙과 팬 사건 화면의 관계·발생 시점은 미정이다.

## 부록 C. 시설·경기장·훈련·난이도

### C-1. 시작과 경기장 등급

- 시설 **0개**, 건설 가능 건물 **5개**, 시작 자금 지급.
- 시작 자금은 처음 시설 **2~3개**를 짓고 나머지는 경기로 벌어 채우는 정도. 모든 훈련시설을 즉시 짓는 자금은 아니다.
- 구체적인 금액은 건설비·연봉·초기 운영비를 함께 보고 정한다. 시설 조합별 가격이 다를 수 있으므로 실제 가능한 시작 선택을 시험한다.
- 자금으로 경기장 등급을 올리면 건물 수 한도가 증가한다. 등급 수·등급별 한도·가격·관중 좌석 변화는 미정이다.
- 시설 철거·교체·중복 건설·건설 소요 시간·환불, 자금 부족 시 유지비 처리도 미정이다.

### C-2. 시설 분류

| 목적 | 사용자 구상 / 후보 | 역할 |
|---|---|---|
| 선수 애정도 | 샤워실·탈의실·마사지실·수면실·선수 식당 | 구단 생활 만족과 애정도 |
| 수익 | 유니폼·굿즈 매장·음식점·편의점 | 관중 소비에 따른 수입 |
| 선수 성장 | 타격·수비·투수·체력 훈련장·전력분석실 | 관련 능력 훈련 가능 |
| 팬 확보 | 팬미팅 공간·어린이 야구 체험장·구단 전시관·홍보/촬영실 **후보** | 팬과 접점·구단 관심 증가 |

- 선수 식당(복지)과 관중 음식점(매출)은 역할이 다르다.
- 팬미팅은 참여 선수 팬, 어린이 체험은 가족의 관람 관심, 전시관은 실제 구단 성과, 홍보실은 선수 콘텐츠와 연결하는 제안이다.
- 시설을 갖췄다고 팬·애정도가 무한히 증가하지 않도록 효과 상한 또는 조건을 검토한다. 매장 매출은 실제 관중과 연동하는 방향이다. 아직 산식이 아니다.
- 시설 유지비를 포함해 설계한다. 건설비·정기 유지비·개별 훈련비를 구분해서 보여준다.
- 시설 자체의 등급 상승은 제안 단계. 같은 건물 수를 유지하며 효과와 유지비가 함께 오르는 안을 검토한다.

### C-3. 훈련

- 해당 시설이 있어야 관련 능력 훈련 가능. 시설만 지었다고 능력치가 자동 상승하지 않는다.
- 기본 연결안: 타격=컨택/파워/선구안, 수비=포구/송구, 투수=구속/제구, 전력분석=야구센스.
- **확정 시설 변경:** 달리기장을 체력 훈련장으로 바꾸고 주력과 스태미나를 각각 자금으로 훈련한다. 총 훈련시설 5종 유지.
- 기존 9개 능력치의 선택 능력 **+1 훈련**과 100 상한을 유지한다. 스태미나 증가 단위·비용·상한은 별도 미정이다.
- 기존 코인 비용 구간(1~49/50~64/65~79/80~89/90~94/95~99에 1/2/3/4/6/8코인)은 **과거 경제 참고값**이다. 자금 전환 후 그대로 사용한다고 확정하지 않는다. 고능력일수록 성장 비용이 커지는 방향과 세분화 의도는 보존한다.
- 버튼에는 자금 아이콘 × 비용, 성장 전후 값, 잔액을 명확히 보여준다. 시설 없음·부족·상한의 이유를 구분한다.

### C-4. 상대 난이도와 운영 균형

- 기존의 **누적 5승 단위 상대 기본 수준 상승**과 같은 구간의 약팀/강팀 무작위 차이를 유지한다. 사용자 능력과 항상 정확히 같게 맞추지 않는다.
- 기존 게임 v05에서 시작 상대 전력을 조금 높인 구현은 과거 조정값이다. 구단 경영·체력·교체를 넣은 난이도를 검증한 결과로 취급하지 않는다.
- 연봉·시설 유지비·훈련비로 운영 선택을 만들되, 복지 할인·매장 수입·인기가 무제한으로 중첩되어 후반 난이도가 사라지는지 확인한다.
- 공격 버튼은 항상 풀스윙만 정답이 되지 않게 한다. 지시는 경향에 영향을 주며 실제 스윙·타구·성공을 보장하지 않는다. 직접 조작의 균형은 재도입 시 별도로 검토한다.
- 시작 자금·승리/패배 수입·유지비·성장 속도·스태미나 소모·공통 성장 한도는 함께 조정한다. 승률 목표·경기 시간 목표는 아직 숫자로 정하지 않는다.

## 부록 D. 경기 진행·버튼 지시·스킵

### D-1. 경기 공통

- 사용자 팀 대 봇, 5이닝, 3아웃 공수 교대. 홈/원정은 기존 각각 50%.
- 5회 동점이면 최대 7회까지 연장, 이후 동점은 무승부. 끝내기와 불필요한 말 공격 생략을 판정에 맞게 처리한다.
- 경기 중 교체 금지는 폐기했다. 세부 교체 규칙은 A-4·I에서 정한다.
- 자동 주루·추가 진루·도루는 유지한다. 현재는 수비수·주자를 방향키로 직접 이동시키지 않는다.
- 반자동·자동·일시정지를 지원한다. 자동 전환·재개로 확정된 결과를 다시 뽑거나 지시 입력 기회를 다시 열지 않는다.

### D-2. 현재 지시 규칙 — 공격·수비 모두 버튼

- 반자동 공격은 매 공, 수비 시프트는 **상대 타자가 들어온 뒤 첫 투구 전 한 번** 지시한다.
- 공격 지시는 해당 공에만 적용하고 다음 공 전에 초기화한다. 변경·취소·예약은 넣지 않는다.
- 수비 시프트는 타석 동안 유지한다. 선수 위치를 고정해 공을 쫓지 못하게 하는 뜻이 아니다.
- 입력 가능 시간은 최대 **10초**. 공격/수비 지시 선택 또는 ‘그대로 해’는 즉시 확정하고 남은 대기를 생략한다. 수비 이동 연출 후 투구하는 시간은 별개다.
- 입력하지 않으면 시간 종료 시 기본 판단으로 진행한다. 자동 경기는 지시 선택 대기가 없다.
- 일시정지에서 이미 지난 입력 기회가 되살아나지 않는다. 공을 놓는 시점과 입력 잠금을 맞춘다.
- 풀스윙=장타 지향/헛스윙 위험, 컨택=맞히기 지향/장타 기대 감소, 참아=선구안 중심. 지시는 경향이며 실제 스윙이나 결과를 보장하지 않는다.

### D-3. 공격 버튼과 실제 행동

- 공격은 **풀스윙 / 컨택 / 참아** 버튼으로 해당 공에 대한 의도를 정한다. ‘그대로 해’는 선수 기본 판단에 맡기고 즉시 진행한다.
- 버튼을 누르면 10초가 끝날 때까지 기다리지 않는다. 선택을 표시하고 입력을 잠근 뒤 투구 준비로 이어진다. 중복 클릭으로 공을 두 번 던지지 않는다.
- 사용자의 지시, 선수의 실제 행동, 판정 결과를 각각 구별한다. 예: ‘지시: 풀스윙 → 실제: 지켜봄 → 볼’은 선구안 판단에 따른 결과로 표시한다. 스윙했다면 볼로 판정하지 않는다.
- 준비·스윙·배트 접촉·헛스윙·지켜봄을 그림으로 구분한다. 상태 문구만 바꾸고 같은 자세를 재생하지 않는다.
- 유지형 게이지는 현재 제외한다. 과거의 무입력 강도 7 고정 문제를 기본 지시 규칙으로 계승하지 않는다.

### D-4. 수비 지시와 자동 움직임

- 수비는 3×3 시프트 버튼과 ‘그대로 해’로 지시한다. 위→아래는 후퇴·기본·전진, 좌→우는 좌·기본·우다.
- 현재 수비수 선택 대기 단계·방향키 이동을 추가하지 않는다. 선택한 시프트로 위치를 옮긴 뒤 투구하고, 타구 추적·포구·송구·커버는 자동으로 수행한다.
- 지시는 출발 배치다. 실제 타구와 선수 판단에 따라 이동하며, 지시한 위치에 고정되거나 결과 성공이 보장되는 것은 아니다.
- **주력과 경기 중 피로가 실제 이동 거리·도착 시간에 반영**되어야 한다. 달리기 그림만 빨리 바꾸거나 모든 선수를 같은 속도로 이동시키지 않는다. 정확한 함수·차이 크기는 체감 검증 후 정한다.
- 타구는 선수 앞뿐 아니라 사이·머리 위·닿기 어려운 곳으로도 갈 수 있어야 한다. 타구 분포는 타자 성향·능력·투구/타격 판정과 연결하고, 포구시키려고 수비수 위치로 낙구점을 옮기지 않는다.
- 공에 도달한 것과 공을 잡은 것을 구분한다. 공 처리 담당·커버 담당을 정해 모든 선수가 한 점으로 몰리거나 순간 이동하지 않게 한다.
- 수동 선수 선택과 이동은 부록 M-7의 미래 계획이다. 현재 자동 수비의 주력·경로·낙구 품질 개선은 그대로 필요하다.

### D-5. 경기 스킵과 요약

- ‘그대로 해’는 현재 입력 대기 생략, ‘남은 경기 스킵’은 경기 종료까지 자동 처리로 구분한다.
- 스킵은 임의 최종 점수를 생성하지 않고 기존 경기 판정을 이어간다. 이미 결정한 플레이를 다시 뽑지 않는다.
- 새 체력·교체·경영 정산도 스킵 경로에서 누락하거나 중복 처리하지 않는다. 자동 교체 기준은 미정이다.
- 종료 후 승패·점수·이닝별 득점·안타·본헤드·투구 수·주요 사건·득점 흐름·개인 기록을 요약한다. 상세 사건 목록이 줄어도 누적 통계는 유지한다.
- 자동·반자동·스킵에 같은 보상 산식을 적용하고, 자금과 트로피는 종료 경기당 한 번만 갱신한다.

## 부록 E. 야구 판정·본헤드·기록 일관성

### E-1. 기본 판정

- 투구 → 공의 영역 → 스윙/지켜보기 → 접촉 여부 → 헛스윙·파울·인플레이 → 수비·주루·결과의 연결을 유지한다.
- 4볼 볼넷, 3스트라이크 삼진, 파울 카운트·사구·희생플라이·태그업·강제 진루·득점은 기존 일반 야구 규칙 기준을 유지한다. 실제 스윙 없이 파울을 만드는 등 불가능한 연결은 금지한다.
- 안타 종류는 타자의 기록이며 다른 주자에게 같은 베이스 수를 일괄 적용하지 않는다. 주력·타구·수비 상황에 따라 추가 진루와 실패가 가능하다.
- 정상적인 도루 실패·포구 실패를 모두 본헤드로 분류하지 않는다. 포구 실책·악송구·폭투·포일은 원인과 책임 기록을 구분한다.
- 병살은 땅볼 처리와 포구 후 귀루 실패 두 유형을 포함한다. 실제 두 명의 아웃을 처리하고 타순은 끝난 타석 하나만 넘긴다. 3아웃과 득점 인정은 아웃의 종류·시점을 고려한다.
- 판단 순서와 애니메이션이 일치해야 한다. 판정과 기록은 사건당 한 번, 시각 재생은 판정 재실행이 아니다.

### E-2. 본헤드 빈도와 집계

- 양 팀 모두 본헤드 가능. 우리 팀 기본은 **한 경기 1~3건**, 능력치에 따라 추가 발생할 수 있다. 능력치가 높아도 기본 본헤드는 사라지지 않는다.
- 최신 상한은 **우리 팀 같은 회의 초·말을 합쳐 최대 3건**. 다음 회에 새로 집계한다. 경기당 10건 상한은 사용하지 않는다.
- 발생 가능한 주자·아웃·타구 조건 안에서만 사건을 만든다. 기본 횟수를 채우려고 불가능한 사건을 강제로 만들지 않도록 분배 방식을 결정해야 한다.
- 공동 사건은 팀 1건, 실제 판단 실수한 선수 각각 개인 1건. 상한은 개인 기록 합계가 아닌 팀 사건 수로 센다.
- 상대 팀의 기본 빈도·상한, 사건 발생 분포와 추가 확률식은 미정이다. 우리 제한을 말없이 상대에도 동일 적용하지 않는다.
- 본헤드 계산의 **야구센스 70%**는 능력 비중이며 발생 확률 70%라는 뜻이 아니다. 나머지 30%를 관련 능력에 균등 배분한다.

### E-3. 본헤드 12종과 동작

| 번호 | 사건 | 연결 능력치 | 같은 그라운드에서 보여줄 동작 |
|---|---|---|---|
| 1 | 홈런인 줄 알고 구경 | 야구센스·컨택·선구안·주력 | 타구 감상→담장 안 낙구→늦게 출발 |
| 2 | 페어 타구를 파울로 착각 | 야구센스·컨택·선구안·주력 | 멈춤→수비 처리→뒤늦게 달림 |
| 3 | 잡혔는데 계속 뛰기 | 야구센스·컨택·주력 | 포구 후 진루→귀루 송구→늦은 귀루 |

- 4·5·6·12번: 야구센스 70, 주력 30%. 7·11번: 야구센스 70, 선구안 30%. 8·10번: 야구센스 70, 송구 30%. 9번: 야구센스 70, 포구 30%.
- 베이스 누락 즉시 자동 아웃, 태그가 필요한 상황에서 베이스만 밟아 아웃 등 잘못된 판정을 하지 않는다.
- **우리/상대 어느 팀의 실수인지 팀 이름·선수 이름·번호와 함께 표시**한다. 공격 중인지 여부만으로 본헤드 팀을 추정하지 않는다.
- 현재 버튼 지시가 잘못되었다는 이유만으로 선수 본헤드 기록을 자동 증가시키지 않는다. 실제 판단 실수 사건을 기록한다. 향후 직접 수비를 다시 넣을 때 입력과 본헤드 동작의 우선순위를 별도로 정한다.

## 부록 F. 화면·공수 시점·낙구 연출

### F-1. 공통 디자인과 기존 피드백 유지

- 밝은 픽셀 야구장, 작은 캐릭터, 남색 패널·파란 테두리·노란 주요 버튼의 승인 시안 방향.
- 점수·볼/스트라이크/아웃·양 팀 타순은 전광판 느낌. 우리 팀 왼쪽, 상대 팀 오른쪽을 유지한다.
- 공격 팀의 현재 타자, 수비 팀의 마지막 완료 타석·다음 타자를 구분한다. 실제 타석이 없는 팀은 ‘마지막’ 표시를 만들지 않는다.
- 각 타순 아래 현재 타자 또는 투수 정보를 표시. 수비 판단용 상대 타자는 이름 식별 외 **좌/우타·당겨/중앙/밀어 성향·파워**만 제공한다.
- 우리 선수의 남은 체력과 공 처리 선수 식별을 추가한다. 직접 조작용 선택 표시는 현재 필수 범위가 아니다. 카드별 수치와 필드 체력바의 노출 범위는 시안을 바탕으로 조정한다.
- 팀 만들기는 선수 미리보기에 집중하고 치어리더를 제외한다. ‘선수와 치어리더, 관객까지 같은 팀·같은 배색’ 및 배색 부위 설명 문구를 노출하지 않는다.
- 팀 메인 치어리더 제거. ‘야구는 언제 끝날지 몰라도 오늘은 한다’ 문구 상자는 왼쪽 하단.
- 경기 양옆 하단의 별도 관중 장식 이미지는 제거하되 구장 관중석은 유지한다.
- 선수·배경 명암과 발 위치·그림자로 접지감을 만든다. 타격→주루 전환 때 갑자기 커지거나 작아지지 않게 원근과 몸 비율을 유지한다.
- 기록실 배경은 전체가 잘리지 않게 보여준다. 성장 비용은 자금 아이콘 × 수량으로 직관적으로 표시한다.

### F-2. 유니폼

- 주/부 색상을 각각 자유 선택. 검정·진홍·빨강·흰색·남색·아이보리·파랑·금색·주황·짙은 와인색·노랑·초록·분홍·보라의 기존 14색.
- 사용자와 상대 팀이 시각적으로 구분되어야 한다. 색 이름만 다르고 화면에서 비슷한 조합은 피하는 방향이다.
- 주 색상은 모자 윗부분·상의·양말, 부 색상은 챙·목깃·소매 끝·번호, 흰 바지·검정 신발의 기존 배색안.
- 양 팀 선수·치어리더·관객은 각 소속 팀의 같은 유니폼과 배색을 공유한다. 상대가 바뀌면 해당 응원 인물도 함께 바뀐다.
- 중계진은 중립 배색. 번호의 가독성과 좌우 반전 시 정방향을 유지한다.

### F-3. 공격 A안 — 확정

- 포수 뒤에서 낮고 가깝게 보는 타격 집중 시점. 타자·배트·투수와 공의 흐름을 크게 보여준다.
- 스윙, 지켜보기, 헛스윙, 배트 접촉을 동작으로 구분한다. 강하게 지시했지만 공을 골랐다면 실제 행동과 결과가 설명되어야 한다.
- **제안:** 타격 후 시야를 넓혀 타구·주루를 보여준다. 타자 혼자 갑자기 축소하지 않고 화면 전체의 원근 전환을 일관되게 처리한다. 전환 속도·범위는 미정.
- A 시안의 예시 수치보다 본문이 우선한다. 공격 버튼은 D-3을 따르고, 좌/우타의 실제 타석 위치와 손·배트 방향은 부록 L을 따른다.

### F-4. 수비 B안과 지시판 — 확정

- 홈 뒤 높은 시점으로 **내야·외야 전체**를 보여준다. 홈은 아래, 외야는 위로 유지한다.
- 수비수 위치·시프트 이동·타구·베이스 커버·주루·실수 책임을 읽을 수 있게 한다.
- 지시판의 3×3 위치를 그라운드 이동 방향과 맞춘다.

| 화면 위치 | 좌 | 기본 | 우 |
|---|---|---|---|
| 위: 후퇴 | 후퇴·좌 | 후퇴·기본 | 후퇴·우 |
| 가운데: 기본 | 기본·좌 | 기본 | 기본·우 |
| 아래: 전진 | 전진·좌 | 전진·기본 | 전진·우 |

- 후퇴는 외야 쪽, 전진은 홈 쪽. 후퇴·우를 선택하면 오른쪽 위 칸과 해당 이동 방향이 일치해야 한다.
- 수비 C 중계 시점은 비교용 미선택안으로 보존하며 기본 수비 화면에 적용하지 않는다.

### F-5. 낙구 지점 안내 — 방향 확정

| 단계 | 표시와 행동 |
|---|---|
| 타격 직후 | 고정 낙구 위치를 희미하지만 식별 가능하게 표시, 넓은 바깥 원, 타구 방향과 자동 수비 출발을 읽음 |
| 공이 내려오는 중 | 같은 위치 표시가 더 선명해지고 바깥 원이 줄어듦, 수비수의 접근을 확인 |
| 포구 직전 | 가장 또렷한 위치 표시, 작은 바깥 원, 공과 수비수의 도착 관계를 확인 |

- **중심 위치는 고정, 선명도는 증가, 바깥 원 크기는 감소**한다. 표적이 무작위로 돌아다니는 방식이 아니다.
- 원은 그라운드 바닥에 붙은 것으로 보이게 한다. 바깥 원은 공 도착까지의 시간을 전달하며 실제 타구 비행과 동기화한다.
- 빠른 타구는 더 빠르게 선명해지고, 높은 뜬공은 천천히 변한다. 마지막 순간에야 처음 나타나 이동 기회를 빼앗지 않는다.
- 낙구 표시는 노란 계열의 시안. 공 처리 선수 강조와 색·모양을 구분한다. 과거 청록색 조작 선수 표시는 직접 조작을 재검토할 때 사용한다. 정확한 색·투명도·크기는 조정 가능하다.
- 표시 도착은 포구 성공 확정이 아니다. 포구·피로·야구센스·본헤드와 실제 공/선수 위치를 함께 판정한다.
- 주 적용은 뜬공. 땅볼 경로·직선타·파울·담장 밖 타구의 표시 방식은 미정이다. 수동 조작은 현재 제외한다.
- 시안의 3개 확대 장면은 시간 흐름 설명용이다. 게임에 작은 경기창 3개를 추가하지 않는다.

### F-6. 일반 플레이·결과·홈런

- 투구→스윙/지켜보기→타격 또는 포구→수비·주루→결과를 같은 경기 공간에서 보여준다.
- 땅볼은 포구·송구·베이스 도달, 플라이/직선타는 실제 포구, 도루는 출발·송구·태그/도달을 구분한다. 병살은 두 아웃을 순서대로 표현한다.
- 본헤드는 같은 그라운드에서 실수→지연→수습으로 보여준다. 별도 작은 영상창이나 결과를 다시 판정하는 리플레이를 추가하지 않는다.
- 볼넷·삼진·아웃·실책 등을 큰 결과 제목과 짧은 이유로 표시하고 읽을 시간을 준다. 최종 결과를 움직임보다 먼저 로그에 공개하지 않는다.
- 기존 게임의 결과 유지 시간(일반 공 1.5초, 주요 결과 3초, 본헤드 3.5초, 홈런 4.5초)은 조정 참고값이다. 5초 리액션이 있으면 결과와 사건을 읽을 수 있게 맞추고, 버튼 지시와 새 캐릭터 동작에서 실제 템포를 다시 확인한다.
- 홈런은 담장 통과→큰 축하·환호→정상 베이스 순회→홈 도착/환영. 상대 홈런도 실제 득점과 순회를 표시한다.
- 끝내기 홈런의 홈런·역전·승리는 한 사건이다. 축하 효과 때문에 리액션·점수·보상을 여러 번 처리하지 않는다.

## 부록 G. 리액션과 멘트

- 화자: 중계진, 우리 치어리더, 상대 치어리더, 우리 관객, 상대 관객.
- **사건 하나당 한 화자 카드만** 오른쪽 상단에 등장한다. 반투명 사각 패널의 **만화 컷** 형태, 인물과 말풍선 함께 표시, 슬라이드 진입/퇴장, **5초 유지**.
- 치어리더 상반신 표시는 오른쪽 상단 리액션에만 적용한다. 팀 만들기·팀 메인에서는 최신 요구대로 치어리더를 제거한다.
- 대사는 사실과 응원 팀에 맞춘다. 우리 실수에는 상대의 놀림·우리 팬의 애증을 강화하고, 상대 실수에 우리 선수를 탓하지 않는다.
- 본헤드로 아웃, 도루 실패와 도루 저지, 끝내기 홈런처럼 원인/결과가 겹쳐도 반응을 여러 개 쌓지 않는다.
- 같은 상황의 후보 3~4개 중 무작위 선택. 직전 같은 문구 연속 억제를 기존 구현 방향으로 유지한다. 무안타 멘트는 6타수 이상 조건을 지킨다.

- 향후 상황마다 **화자별 3~4개씩** 늘리는 계획은 현재 상황당 4개와 다르다. 미래 계획으로 구분한다.
- 팬 이벤트·저체력·교체·시설·연봉 전용 문구는 별도 작성 대상이다. 기존 경기 반응 규칙을 임의로 늘리지 않는다.

## 부록 H. 저장·복구·구버전 전환

### H-1. 저장 2칸과 백업

- 게임 진행 저장칸은 총 **2개**. 빈 칸에 새 게임, 모두 차 있으면 사용자가 한 칸을 선택해 삭제 확인 후 새 게임을 만든다.
- 불러오기·삭제·처음부터 다시 하기는 대상 팀과 저장칸을 보여주고 확인한다. 취소하면 원래 상태 유지.
- 선택한 칸 하나를 파일로 백업하고, 파일 불러오기도 대상 칸을 선택한다. 파일을 가져온다고 세 번째 칸이 생기지 않는다.
- 잘못된 저장 파일은 오류를 설명하고 기존 데이터를 유지한다. 다른 칸의 선수·자금·기록을 바꾸지 않는다.

### H-2. 저장할 항목과 경기 복구

- 팀·배색, 선수 ID/외형/번호/능력/기록/팬/애정도/계약, 출전/후보·편성 초안, 자금·승패·시설·경기장·보상/거래 완료 상태.
- 경기 상대·홈원정·이닝·카운트·아웃·주자·타순·점수·선수별 남은 체력·교체 이력·지시·모드·본헤드 회별/경기별 집계·요약 기록.
- 마지막 판정이 완료된 공 이후 상태에서 이어가며 아웃·득점·기록·소모·정산을 중복 반영하지 않는다.
- 메인에서 이어하기 확인 후 경기 화면은 일시정지 상태로 열고, ‘경기 재개’를 눌러 진행한다. 자동 경기 중 중단했어도 먼저 재개를 기다린다.
- 동작 재생 도중 새로고침해도 완료된 판정은 다시 뽑지 않는다. 확정 결과·체력·기록의 일관된 상태로 복구한다. 향후 직접 수비를 재도입하면 입력·이동 경로의 복구 기준을 추가 설계한다.

### H-3. 기존 저장 호환 — 구현 전 필수 설계

- 현재 게임 v06 저장을 새 경영 버전 저장과 구분할 데이터 형식 버전을 둔다. 파일명 버전과 혼동하지 않는다.
- 기존 코인→자금 비율, 기존 9명 팀에 후보 3명을 추가 지급할지, 기존 선수의 스태미나·연봉·팬·애정도 초기값, 시설/경기장 초기값은 미정이다.
- 기존 미결정 무료 영입·15코인 선택의 처리, 진행 중 경기의 체력 초기화 시점과 구 규칙 종료 방식도 결정해야 한다.
- 확정 전 자동 변환·선수 삭제·저장 초기화를 하지 않는다. 원본 백업과 실패 시 복구 가능한 방식으로 설계한다.
- 브라우저별 로컬 저장이며 계정·기기 간 자동 동기화는 포함하지 않는다. 비밀번호·API 키를 저장하지 않는다.

## 부록 L. 선수 디자인·전체 동작·글꼴 — 2026-09-21 통합

### L-1. 선택한 그림체와 적용 상태

- 사용자가 처음 의도한 느낌은 스타듀밸리·카이로소프트처럼 **작고 또렷한 전신 픽셀 캐릭터**다. 해당 게임의 캐릭터나 그림 파일을 복제하는 뜻은 아니다. 해체해라 자체 캐릭터와 유니폼을 사용한다.
- 작은 도트, 간결한 얼굴, 일정한 몸 비율을 유지한다. 약 2~2.5등신은 현재 시안의 비율 참고이며 최종 픽셀 수·해상도는 미정이다.
- 얼굴·팔·몸을 따로 잘라 크게 돌리는 인형 같은 움직임에서 벗어나, **동작 전체가 이어지는 전신 자세**를 기본으로 한다. 프레임은 애니메이션을 이루는 한 장의 자세 그림이다.
- 구장을 다시 꾸미기보다 선수의 모양·개성·속도·타격/투구 모션을 먼저 다듬는다. 승인한 공수 카메라와 기존 화면 기능은 유지한다.
- 작업 순서는 **필요 동작 그리기 → 실제 경기 화면 배치 → 연결·속도·효과 확인 → 경기 판정과 연결**이다. 시안 제작이나 대표 배치 확인만으로 모든 동작이 완성되었다고 간주하지 않는다.

### L-2. 같은 선수로 보이는 특징

- 선수마다 외형 특징을 저장하고 관리 화면·라인업·필드·결과에서 동일하게 사용한다. 머리 모양/색·피부·얼굴 특징·안경/수염 등 조합은 디자인 후보이며, 유니폼 색만으로 개성을 대신하지 않는다.
- 이름·번호는 실제 선수 데이터와 일치하고 읽을 수 있어야 한다. 작은 필드에서 번호를 항상 크게 넣기 어렵다면 현재 타자/투수 카드·선수 강조와 함께 식별하게 한다. 구체적인 상시 이름표 범위는 가독성 검토 후 정한다.
- 좌/우타와 선수별 준비 자세·스윙 마무리·투구 자세를 구분하는 방향이다. 전용 타격/투구 유형 수·배정 방식·신규 능력 보정은 아직 확정하지 않았다.
- 외형이나 투구폼만 보고 새 숨은 능력이 생겼다고 오해하게 하지 않는다. 기존 능력치·주력·피로가 실제 플레이를 결정한다. 몸 크기 변화로 파워나 주력을 임의 표현하지 않는다.

### L-4. 속도·효과·결과 읽기

- 주력은 동일한 시간 동안 움직인 실제 거리에서 차이를 보여야 한다. 걷기/달리기 발 교대는 이동 거리와 맞춰 미끄러지는 느낌을 줄인다. 체력 영향 수치는 I의 미정 항목을 따른다.
- 컨택은 짧고 간결하게, 풀스윙은 큰 회전과 마무리로 구분하되 **이 차이가 강한 타구를 보장하지 않는다**. 투구폼 종류는 연결 자세를 더 다듬은 후 확정한다.
- 배트 접촉의 짧은 궤적·충격 표시, 달리기/슬라이딩의 발밑 먼지는 공과 몸을 가리지 않는 보조 효과로 사용한다. 지켜보기·헛스윙에 타격 접촉 효과를 붙이지 않는다.
- 볼·스트라이크는 카운트 변화, 삼진·볼넷·아웃은 큰 결과 제목과 짧은 설명으로 구별한다. 핵심 플레이가 보이기 전에 결과만 먼저 지나가지 않게 한다.
- 원인 동작 → 필요한 수비/주루 → 판정 표시 → 읽을 시간 → 다음 입력 순서를 지킨다. 본헤드의 멈칫함·뒤늦은 수습과 상대의 놀림이 같은 사건으로 읽혀야 한다.
- 0.75/1/1.25배 속도·효과 끄기·시간 막대·발 기준 표시 등은 **동작 검토 도구**다. 이를 본 게임의 새 속도 설정으로 자동 확정하지 않는다.
- 게이지와 함께 점점 커지는 불꽃은 M-7의 미래 연출이다. 현재 버튼 버전의 필수 효과로 혼입하지 않는다.

### L-9. 실제 경기 화면에서 통과해야 할 디자인 확인

1. 같은 선수를 이름·등번호·외형으로 관리 화면과 경기에서 알아볼 수 있다.
2. 공격·수비 시점 모두 좌/우타 위치가 다르고, 공을 던지는 방향과 몸/손이 맞는다.
3. 준비→스윙→주루, 포구→송구에서 크기가 갑자기 바뀌거나 발이 뜨지 않는다.
4. 같은 출발점·목적지·시간에서 주력 차이가 실제 이동에 보인다. 능력/피로 차이와 별개로 타구를 잡도록 순간 이동시키지 않는다.
5. 타격했는지 지켜봤는지, 왜 아웃/세이프인지 눈으로 이해할 수 있다. 홈런·병살·본헤드는 사건과 기록이 일치한다.
6. 선수 앞·사이·멀리 떨어진 타구 모두 자연스럽게 추적하며, 도달 실패/포구 실패/본헤드를 구별한다.
7. 주요 결과와 리액션을 읽을 수 있고, 큰 글씨/세부 글씨의 역할이 구별된다. 글꼴 검증은 실제 적용 요청 후 수행한다.
8. 대표 동작만이 아니라 일반 플레이·12종 본헤드·교체·자동/스킵·복구를 함께 검증해야 최종 완료다.

## 부록 M. 추후 추가할 계획

이 부록은 문서의 마지막에 둔다. 현재 요청한 시설·연봉·팬·스태미나·교체와 미정 수치 목록을 미래 기능으로 밀어내지 않는다.

### M-1. 상황별·화자별 멘트 확장

- 중계진·우리/상대 치어리더·우리/상대 관객 각각에 대해 상황별 3~4개씩 문구를 추가한다.
- 현재는 상황당 후보 총 4개다. 모든 화자가 각각 4개씩 갖춘 것으로 표시하지 않는다.
- 문구가 늘어도 한 사건 한 화자·팀과 상황에 맞는 반응 규칙을 유지한다.

### M-2. MLB 진출·선수 판매

- 성장한 선수를 MLB로 보내고 **구단 자금을 받는 방향**. 진출 선수는 현재 선수단에서 빠지고 새 선수 육성으로 이어진다.
- 매각 실패 시 구단 애정도가 크게 떨어지는 사건을 구상했다. 조건·성공 확률·금액·선수 의사·실패 원인·불만 크기는 미정이다.
- 잘 키워 보냈다는 만족을 만들되 강제 은퇴·자동 매각을 확정하지 않는다. 후임 선수 자동 지급·별도 진출 명단도 미정이다.
- 진출 이후 출전 9명을 유지할 방법과 누적 기록 보존을 함께 정한다.

### M-3. 업적·칭호·특별 유니폼

- MLB 진출 인원·누적 승리 등으로 업적을 연결하는 방향.
- 과거 코인/트로피 보상 구상은 새 자금·승리 트로피 정의에 맞춰 다시 정한다. **트로피는 승리 수이므로 업적 보상으로 증가시키지 않는다.** 자금이나 별도 업적 표식을 검토한다.
- 팀 칭호·특별 유니폼은 후속 확장. 종류·조건·효과 미정. 기본 자유 배색과 팀별 유니폼 연동은 현재 요구다.

### M-4. 직접 주루 지시

- 추후 사용자가 도루·진루 등 주루를 지시하는 기능을 검토한다. 현재는 자동 주루 판단.
- 현재 버튼 수비 및 추후 직접 수비 구상이 직접 주루 지시까지 포함하는 것은 아니다. 종류·입력 시점·취소·대상 선택은 미정이다.

### M-5. 휴대폰 화면·조작

- PC 중심 완성 후 양옆 타순·공격/수비 버튼·리액션·경영 화면을 터치와 작은 화면에 맞춘다. 직접 조작은 재도입을 결정했을 때 별도로 검토한다.
- 계정이나 기기 간 자동 저장 동기화는 이 계획에 자동 포함하지 않는다.

### M-6. 다른 작업 중 보는 소형 경기 패널

- 사용자가 창을 아래로 내렸을 때 작은 팝업처럼 경기 진행과 선택지를 볼 수 있는 구상.
- 수동 경기일 때 진행 상황과 선택 버튼, 자동 경기일 때 진행 상황 중심으로 보여주는 방향.
- 실제 창 최소화 감지·다른 앱 위 표시·브라우저 지원 범위·권한·동작 방식은 추후 검토한다. 일반 웹페이지에서 이미 가능한 기능이라고 약속하지 않는다.

### M-7. 타격 게이지·수비 직접 조작·불꽃 — 현재 보류

- 사용자가 직접 플레이한 뒤 **공격·수비 모두 버튼이 편하다**고 결정했다. 아래는 삭제할 아이디어가 아니라, 나중에 다시 재미를 확인할 계획이다. 현재 구현 완료 조건에 넣지 않는다.
- 공격 B 구상: 스페이스/마우스를 누르면 강도가 올라가고 떼면 내려가며, 다시 눌러 원하는 구간을 유지한다. ‘떼는 순간 즉시 확정’이나 자동 왕복 바 멈추기 방식과 구별한다.
- 채택했던 확정 시점은 **투구 시작 직전 한 번**이다. 미리보기 v03은 10초 만료 또는 ‘이 강도로 시작’/Enter를 사용했다. 입력을 한 적 없는 상태는 선수 판단, 입력 후 0까지 내려간 상태는 의도한 0으로 구분했다. 상승 1.6초/하강 2.4초는 당시 임시값이며 최종 수치가 아니다.
- 미래 불꽃은 타자 주변에서 지시 강도에 따라 점점 커진다. 낮은 파워 선수가 활활 타는 불꽃 뒤 공을 ‘틱’ 하고 약하게 보내는 기대/결과 대비를 노린다. 불꽃이 파워 수치·홈런 보장·항상 약한 타구를 뜻하지는 않는다.
- 수비 구상: 투구 전 시프트 후 타구 방향에 맞춰 수비수를 선택하고 방향키로 이동한다. 선택 과정·강조가 명확해야 한다. 최근 연속형 미리보기는 가까운 선수 자동 선택/클릭 변경을 사용하고 별도 2초 정지는 없앴으나, 이를 재도입할 최종 방식으로 확정하지 않는다.
- 재검토할 항목: 선택 방식, 입력과 자동 수비의 전환, 이동 종료·송구, 본헤드 중 입력 우선순위, 무입력 처리, 게이지/불꽃 속도, 공 비행 시간과 개입 여유, 경기 소요 시간과 피로감.
- 수동 조작을 하지 않는 자동 경기·스킵에도 같은 능력·체력·판정 원칙을 적용한다. 직접 조작 보상 배율은 별도 결정 없이 추가하지 않는다.
