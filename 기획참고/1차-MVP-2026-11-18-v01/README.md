## 남은 문제와 이번에 얻은 기준

- **사용자가 지적한 핵심 문제:** 기능 증가로 여러 화면이 복잡해짐. 부분 수정을 반복하는 데 시간이 너무 많이 듦.
- 경기 화면의 정보·조작·캐릭터 움직임이 서로 가리는 문제를 반복해서 조정했습니다. 새 설계에서는 무엇을 계속 보여주고 언제 펼칠지를 먼저 정합니다.
- 캐릭터 방향, 얼굴 위치, 파츠 연결, 체형·자세별 조합은 반복 수정 대상이었습니다. 모든 조합의 시각 품질 승인을 받은 상태는 아닙니다.
- A1·A2·A9(저장 크기/속도, 캐릭터 메모리, 강제 종료 뒤 저장 보호)는 이전에 보류한 항목입니다. 전체 해결로 기록하지 않습니다.
- P27의 성과 점수 기반 동행·19세 회춘, 회춘권은 기획 상태이며 구현 목록에 포함하지 않습니다. 별도의 기존 MLB 회생권과 구분합니다.
- 장기 경제·성장 균형과 일부 오래된 검사 기대값은 미해결 검토 사항입니다. 과거의 통과 검사 결과를 전체 품질 보증으로 확대하지 않습니다.
- 이번 보존 작업에서는 새 게임 플레이 시험을 수행하지 않았습니다. 최근 경기 검수와 각 기능의 기존 시험 기록을 연결해 보관합니다.

## 보존 및 실행

1. 위 태그를 별도 폴더에 받아 당시 소스를 확인합니다. 기존 작업 폴더를 강제로 되돌리지 않습니다.
2. 저장소 루트에서 `python tools/build-web.py`를 실행하고 생성된 `dist/`를 로컬 정적 서버로 엽니다. 최신 웹 기준은 `dev.html`과 연결된 `src/`·`assets/`입니다.
3. 제공 원본의 ‘v27’, 현재 Site의 ‘버전 28’, ‘1차 MVP’는 서로 다른 이름 체계입니다. 이전 단일 HTML을 최신 웹 기준본으로 오인하지 않습니다.
4. Git으로 추적되는 코드·자산·기획·시안은 태그에 보존됩니다. 아직 Git에 넣지 않은 로컬 초안은 원래 위치에 남으며 태그의 범위가 아닙니다. 개인 구단 저장 데이터는 이 기준본에 수집하지 않습니다.
