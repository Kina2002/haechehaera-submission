# 기획서(PRD) : 《해체해라》

> 선수들은 알아서 야구하고, 사용자는 필요할 때 감독처럼 개입합니다.
> 황당한 플레이에 “아놔…” 하면서도 “어떻게든 이기고 만다”는 마음으로 다시 경기하게 만드는 게임입니다.

작성일: 2026-09-11  
버전: v05  
기획: 사용자 / 문서 정리: Codex  
상태: **기존 v04의 게임 규칙과 이후 화면·유니폼·연출·멘트 논의를 통합한 새 PRD. 시안과 멘트 후보는 작성했으며, 실제 게임·애니메이션·무작위 표시 기능은 아직 구현하지 않음.**

## 이 문서의 기준

- 근거는 **이번 대화에 첨부한 《해체해라》 최신 기획안과, 그 뒤 사용자와 나눈 기획 수정 대화**입니다.
- **이전 야구 게임, 기존 코드·기획서·사이트, 이번 대화 중 잘못 이어서 만든 경기 수정본은 요구사항의 근거로 사용하지 않습니다.** 그 게임의 화면 배치, 버튼, 확률 수치, 구현 제약을 가져오지 않습니다.
- 뒤에 나온 사용자 결정이 첨부 원문의 같은 항목을 수정합니다. 사용자가 바꾸지 않은 원문의 기능은 유지합니다.
- **기본 원칙은 일반 야구 규칙을 따르는 것입니다.** 경기 판정·진루·득점·공식 기록은 이 원칙을 적용하며, 문서에 개별 규칙이 적혀 있지 않다는 이유만으로 제외하지 않습니다. 사용자가 별도로 정한 게임의 예외는 우선 적용합니다. 이후에는 일반 규칙의 포함 여부를 반복해서 묻지 않고, 게임 고유의 선택이나 규칙 간 충돌이 있는 부분을 확인합니다.
- 이 문서에서 **확정**은 원문 또는 이후 사용자 발언으로 정한 내용, **논의안·적용안**은 제안됐지만 세부 선택이 확인되지 않은 내용, **미정**은 아직 정하지 않은 내용입니다.
- **이번에는 사용자가 새 통합 버전을 요청했으므로 v05를 새 파일로 작성했습니다.** 이전에 v04를 직접 갱신하던 방침보다 이번 요청을 우선하며, 기존 PRD v01~v04와 멘트 초안 v01~v02는 보존합니다. 현재 통합 기준은 이 v05입니다.
- 기존 게임 규칙은 본문과 부록 A~E, 결정 현황은 F, 검증 계획은 G, 화면·연출은 H, 반응 규칙과 168개 멘트 후보는 I, 참고 시안과 문서 상태는 J에 정리했습니다. **추후 추가할 기능은 문서 마지막의 부록 K에 모았습니다.**
- 시안의 픽셀 배치·예시 이름·등번호·능력치·날짜가 본문의 게임 규칙을 덮어쓰지 않습니다. 확정된 요구와 검토용 적용안을 구분하며, 일부 작은 글자·동작의 생성 오류가 남은 시안은 방향 참고 자료로 사용합니다.
- 이번 결과물은 문서입니다. **이 문서를 저장하거나 열었다는 이유로 게임을 구현·수정·실행·게시하지 않습니다.** 이후 사용자가 구현을 별도로 요청하면 이 문서를 기준으로 진행합니다.

## 1. 풀고자 하는 문제

- **현재 구상:** 2D 픽셀 야구 선수 수집·육성 게임입니다. 선수가 투구·스윙·타격·주루·수비를 수행하고, 사용자는 감독으로 선수와 전략을 관리합니다.
- **만들고 싶은 경험:** 선수마다 다른 강점과 약점을 보고 배치하고 키우지만, 경기에서는 엉뚱한 판단과 실패가 일어나 약이 오르는 경험입니다.
- **재도전의 이유:** “다음엔 어떻게든 이기고 만다.” 패배 후에도 성장과 편성을 통해 다음 경기를 준비할 수 있어야 합니다.
- **재미의 중심:** 사용자를 ‘킹받게’ 만드는 상황과 반응입니다. 감독의 지시 실수, 선수의 엉뚱한 플레이, 해설과 상대 반응이 이 경험을 만듭니다.
- **표현 원칙:** 카이로소프트 계열처럼 직관적이고 귀엽고 읽기 쉬운 경영게임 형태의 2D 픽셀 화면을 지향합니다. 웃음은 경기 사건과 대사에서 만들며, 화면 자체를 밈처럼 꾸미지는 않습니다.
- **이번 프로젝트의 크기:** 짧게 즐길 작은 프로젝트입니다. 선수 수집·육성·편성은 이번 핵심 범위에 포함하고, MLB 진출처럼 장기 플레이를 위한 확장은 나중으로 미룹니다.

## 2. 사용자

- **누가:** 야구의 기본 규칙과 포지션에 대한 지식이 있는 사람.
- **언제:** 가볍게 경기를 즐기고, 팀을 조금씩 키우며 재도전하고 싶을 때.
- **어디서:** 우선 PC의 웹 브라우저. 휴대폰에서도 편하게 보이고 조작되는 화면은 향후 추가합니다.
- **플레이 시간:** 경기 내용에 따라 달라집니다. 한 경기의 고정 소요 시간을 정하지 않습니다. 공 사이 간격과 자동 경기 속도는 실제 플레이를 보며 조정합니다.

## 3. 입력 자료

| 구분 | 입력 또는 자료 |
|---|---|
| 팀 설정 | 팀 이름, 유니폼 주 색상·부 색상 각각 선택 |
| 선수 설정 | 선수 이름, 등번호 |
| 경기 전 편성 | 출전 9명, 수비 포지션 9곳, 1~9번 타순 |
| 경기 중 입력 | 공격 지시, 수비 깊이와 시프트, 일시정지, 자동 경기 전환 |
| 성장 입력 | 성장시킬 선수와 능력치 선택, 코인 사용 |
| 영입 입력 | 신규 선수 확인, 영입 여부와 필요 시 기존 선수 교체 |
| 게임이 생성할 자료 | 초기 선수, 신규 선수, 상대 팀, 홈·원정, 경기 결과와 사건 |
| 저장 자료 | 각 사용자의 브라우저에 최대 2개 저장칸으로 보관하는 서로 독립된 팀·게임 진행 데이터, 선택한 저장칸의 백업 파일 |
| 준비가 필요한 자료 | 시안을 바탕으로 만들 실제 선수·인물·경기 동작 자료, 선수·팀 이름 후보, 최종 선별할 반응 문구, 경기 판정 확률과 상대 전력 수치 |

- 계정 정보나 민감 개인정보를 입력받지 않습니다. 선수는 게임 내 가상 인물입니다.
- **이름 설정 확정:** 팀·선수 이름을 자동으로 제안하고 사용자가 수정할 수 있습니다. 팀 이름은 1~12자, 선수 이름은 1~8자이며 경기 밖에서 변경할 수 있습니다.
- **등번호 설정 확정:** 등번호는 0~99의 정수입니다. 사용 가능한 번호를 자동으로 제안하고 사용자가 직접 변경할 수 있습니다. 같은 팀의 보유 선수 전체에서 등번호가 겹치지 않게 합니다.

## 4. 핵심 기능(MVP: 첫 완성 버전의 범위)

| 묶음 | 사용자가 할 수 있어야 하는 것 | 상세 기준 |
|---|---|---|
| 1. 선수 수집과 편성 | 처음 받은 9명과 영입한 선수를 관리하고, 최대 15명 중 출전 9명의 포지션·타순을 정합니다. | 부록 A |
| 2. 반자동·자동 경기 | 선수 움직임을 보며 5초 선택 시간에 공격·수비 지시로 개입하고, ‘그대로 해’로 대기를 생략합니다. 자동 경기와 일시정지도 사용합니다. | 부록 B·H |
| 3. 경기 판정과 코미디 | 병살·실책·폭투·포일·본헤드를 그라운드의 움직임으로 보고, 사건당 한 화자의 무작위 멘트와 큰 홈런 축하를 경험합니다. | 부록 C·H·I |
| 4. 성장과 보상 | 경기 완료 시 기본 1코인+내 팀 득점, 매 승리 트로피+1과 영입 기회 1회를 받고 성장·재편성합니다. | 부록 D |
| 5. 기록과 저장 | 최대 2개의 팀·진행을 별도로 저장하고 이어하기·백업·불러오기·처음부터 다시 하기를 사용합니다. 불러오기·삭제·초기화 전에 확인합니다. | 부록 E |

**반복 흐름**

저장칸 선택 → 새 팀 시작 또는 저장된 팀 불러오기 → 새 팀이면 이름·유니폼 설정과 초기 선수 9명 생성 → 포지션·타순 편성 → 경기 → 결과·보상 → 선수 성장·영입 → 재편성 → 다음 경기

- 초기 선수 9명은 **새 팀을 시작할 때** 지급합니다. 매 경기마다 선수단을 새로 만들지 않습니다.
- 저장칸은 **1번·2번 두 개**입니다. 빈 칸에는 새 게임을 만들 수 있고, 두 칸이 모두 차 있으면 기존 하나를 선택해 삭제한 뒤 그 자리에 새 게임을 만듭니다. 상세 확인·취소 동작은 부록 E를 따릅니다.
- 다음 경기로 넘어가도 팀, 보유 선수, 성장한 능력치, 누적 기록, 코인, 트로피는 이어집니다.
- 승리 후에는 **선수를 영입하거나 거절 보상 15코인을 수령하는 결정을 완료한 뒤에만 다음 경기를 시작**할 수 있습니다. 영입 결정을 미뤄 두는 기능은 넣지 않습니다.
- **Codex가 향후 맡을 일:** 이 문서에 따른 화면, 선수 생성, 경기 판단, 확률 계산, 기록, 성장·보상, 저장과 검증 구현.
- **게임 안의 AI가 맡을 일:** 상황에 따른 기본 지시와 선수의 플레이 판단. 여기서 AI는 게임 내부 판단 로직을 뜻하며 외부 생성형 AI 서비스 연결을 뜻하지 않습니다.
- **사용자가 확인할 일:** 지시와 결과가 이해되는지, 황당한 순간이 의도한 재미로 느껴지는지, 패배 후 재도전과 성장 흐름이 유지되는지.

| 경기 결과 | 승리·패배·무승부, 점수, 기록, 코인·트로피 보상, 도발 멘트, 다음 경기 준비 동선 |

- 8개 화면은 필요한 기능 구분입니다. 인터넷 주소를 8개 만들거나 기술적으로 별도 페이지를 8개 만들기로 확정한 것은 아닙니다.
- 그라운드의 선수 움직임을 보고 지시하는 경험을 구현할 계획입니다. 최신 화면 구성·정보 배치·팀색·반응 위치와 연출 방향은 부록 H에 통합했습니다. 정확한 픽셀 치수·카메라 이동·동작 시간·음향은 남은 세부 설계이며, 과거 사이트의 화면을 기본안으로 사용하지 않습니다.

### 5-3. 향후 게임의 완료 조건

1. 새 팀에 강점·약점이 있는 초기 선수 9명이 생성됩니다. 강점이 야구센스이면 60~70, 다른 능력치이면 75~100이며, 약점은 1~25, 나머지 7개는 20~55입니다.
2. 이후 영입은 야구센스 1~70, 다른 8개 능력치 각각 1~100의 정수를 독립적으로 같은 확률로 뽑습니다. 모든 능력치는 훈련으로 최대 100까지 성장할 수 있습니다.
3. 9개 능력치와 경기 기록을 구분해서 사용자에게 표시합니다. 선수 관리에서는 전체 누적 기록, 라인업에서는 핵심 기록 2~3개와 전체 상세 보기를 제공합니다. 몸에 맞는 공(사구)과 희생플라이를 경기·개인 기록에 포함하고, 타율·출루율·장타율은 실제 기록과 공식 산식으로 계산합니다. 폭투는 투수, 포일은 포수의 별도 기록으로 집계하며 그 폭투·포일 자체를 실책 개수에 더하지 않습니다.
4. 보유 선수 중 서로 다른 9명을 선택하고, 포지션과 타순을 빠짐없이 편성할 수 있습니다.

### 5-4. 누락·실패 상태

- 편성에 중복 선수, 비어 있는 포지션 또는 타순이 있으면 경기 시작 전에 무엇을 고쳐야 하는지 안내합니다.
- 코인이 부족하거나 능력치가 상한에 도달했으면 성장 불가 이유를 표시하고 코인을 차감하지 않습니다.
- 선수 방출·교체로 기록이 사라질 경우 확인창에서 안내합니다.
- 저장 또는 불러오기에 실패하면 이유를 이해할 수 있는 안내를 표시합니다. 실패를 성공으로 표시하거나 기존 진행 데이터를 조용히 초기화하지 않습니다.

## 7. 만드는 방식과 공유 방법

- 선택: **도구·웹** — 사용자가 브라우저에서 반복해서 즐기는 게임입니다.

- 게임 내부 판단은 외부 AI 서비스 호출 없이 처리합니다. 게임 플레이에 개발자의 API 인증값이나 AI 사용 토큰을 사용하지 않는 구조입니다.
- 향후 완성 파일 또는 폴더를 전달할 수 있습니다. 인터넷 게시 여부, 새 주소와 접근 범위는 별도 요청 시 정합니다. **기존 사이트나 게시 주소를 이어 쓰기로 정하지 않았습니다.**

### A-1. 팀과 선수 생성 — 확정

- 팀 설정은 팀 이름과 유니폼의 주 색상·부 색상입니다. 공통 14색 선택지, 봇과의 색상 구분, 선수·치어리더·관객 간 연동은 H-3을 따릅니다.
- 초기 선수는 9명입니다. 각 선수에게 서로 다른 능력치 2개를 무작위로 골라 강점 1개와 약점 1개로 지정하고, 나머지 7개도 아래 범위에서 생성합니다.

| 초기 선수의 능력치 구분 | 생성 범위 |
|---|---|
| 강점이 야구센스인 경우 | 60~70 |
| 강점이 다른 능력치인 경우 | 75~100 |
| 약점 1개 | 1~25 |
| 나머지 7개 | 각각 20~55 |

- 초기 선수에게 포지션 보정은 하지 않으며, 좋은 투수를 반드시 주는 식의 보장도 없습니다.
- 이후 영입 선수는 **각 능력치를 아래 정수 범위에서 같은 확률로 독립적으로 생성**합니다. 다른 능력치의 값에 맞춰 높이거나 낮추는 균형 보정은 하지 않습니다.

| 이후 영입 선수의 능력치 | 생성 범위 |
|---|---|
| 야구센스 | 1~70 |
| 컨택·파워·선구안·주력·포구·송구·구속·제구 | 각각 1~100 |

- **야구센스는 선수 뽑기에서 70을 넘지 않습니다.** 초기 선수의 강점 예외도 이 상한을 지킵니다. 훈련으로 올릴 수 있는 상한은 다른 능력치와 같이 100입니다.
- 팀·선수 이름은 자동으로 제안하고 사용자가 수정할 수 있습니다. 팀 이름 1~12자, 선수 이름 1~8자이며 경기 밖에서 변경 가능합니다.
- 등번호는 **0~99의 사용 가능한 정수를 자동으로 제안하고 사용자가 직접 변경**할 수 있습니다. **같은 팀의 보유 선수끼리 중복할 수 없습니다.** 초기 선수와 신규 영입 선수 모두 이 기준을 적용합니다.
- 좌타·우타와 타구 방향 성향은 랜덤입니다.
- 타구 방향 성향은 당겨치기·중앙·밀어치기입니다. 타자의 좌우타에 맞는 실제 타구 방향과 수비 시프트가 일관되게 연결되어야 합니다.
- 그라운드 좌우는 홈에서 중견수 방향을 바라보는 기준으로 설명합니다. 우타자의 당겨치기는 좌측, 밀어치기는 우측이며 좌타자는 반대입니다. 성향은 타구 방향의 경향이며 모든 타구의 방향을 고정하지 않습니다.

### A-2. 능력치 9개

능력치는 **1~100**까지 성장할 수 있습니다. 선수 생성 시 야구센스는 최대 70이며, 초기 선수의 능력치 범위는 A-1을 따릅니다. 기존 명칭 ‘수비센스’를 **야구센스**로 바꾸며 능력치 종류는 9개를 유지합니다.

| 구분 | 능력치 | 역할과 영향 |
|---|---|---|
| 타격 | 컨택 | 공을 배트에 맞히는 능력. 헛스윙·파울·인플레이에 영향. 인플레이는 공이 경기장 안으로 들어가 수비·주루 판정으로 이어지는 타구입니다. |
| 타격 | 파워 | 강한 타구를 만드는 능력. 장타와 홈런에 영향 |
| 타격 | 선구안 | 좋은 공과 나쁜 공을 구분하는 능력. 스윙 여부와 ‘참아!’ 지시에 중요 |
| 주루 | 주력 | 추가 진루·도루 성공과 수비 시 타구 위치에 도달하는 능력 일부에 영향 |
| 공통 판단 | 야구센스 | 공격·주루·수비 상황의 판단과 본헤드 발생에 영향. 기존의 어려운·애매한·불규칙한 타구 판단과 다이빙 캐치 관련 수비 역할도 유지 |
| 수비 | 포구 | 공에 도달한 뒤 잡는 능력. 포구 실책과 포일에 영향 |
| 수비 | 송구 | 잡은 공을 정확하게 던지는 능력. 악송구와 주자 진루 저지에 영향 |
| 투구 | 구속 | 투구 위력. 헛스윙과 타구의 질에 영향 |
| 투구 | 제구 | 원하는 곳에 던지는 능력. 볼·스트라이크, 볼넷과 폭투에 영향 |

본헤드 판정에서 야구센스의 비중은 **70%**로 정했습니다. 본헤드 12종의 연결 능력치와 확정된 비중은 C-5에 정리합니다. 일반 경기 판정의 정확한 확률과 포지션별 비중은 향후 조정합니다.

### A-3. 누적 경기 기록

능력치와 기록은 별도입니다. 기록은 실제로 진행한 경기에서 누적합니다.

| 구분 | 항목 |
|---|---|
| 타격 | 경기, 타석, 타수, 안타, 2루타, 3루타, 홈런, 볼넷, 몸에 맞는 공(사구), 희생플라이, 삼진, 타점, 득점 |
| 비율 기록 | AVG(타율), OBP(출루율), SLG(장타율) |
| 투구 | 등판, 이닝, 실점, 탈삼진, 볼넷, 폭투 |
| 수비·특수 | 실책, 포일, 본헤드 플레이 횟수 |
| 병살·굴욕 | 병살 기록, 최근 무안타, 해당 경기 헛스윙, 본헤드 누적을 확인할 수 있는 정보 |

- 타율·출루율·장타율은 실제 누적 기록에서 공식 산식으로 계산합니다. 사구·희생플라이와 출루율의 집계 기준은 A-3-3에 확정했습니다. **실제 횟수가 0이면 0, 아직 계산할 수 없는 비율은 ‘—’로 표시합니다.** 계산 가능한 비율의 값이 0인 경우와 계산 자체가 불가능한 경우를 구분합니다.
- 투구 이닝은 실제 잡은 아웃 수와 맞아야 합니다.
- ‘최근 무안타’는 마지막 안타 이후의 연속 무안타 타수로 집계하고 **6타수 이상부터 멘트를 표시**합니다. 상세 기준은 A-3-4를 따릅니다. 병살 기록의 선수·팀별 표시 범위 등 화면 세부 사항은 추후 정합니다.

#### A-3-1. 본헤드 개인·팀 집계 — 확정

- 선수 개인의 본헤드 누적 기록과 팀의 본헤드 사건 횟수를 다음 기준으로 구분해 집계합니다.
- **한 사건은 팀 본헤드 1회로 세고, 실제 판단 실수를 한 선수에게 각각 개인 본헤드 1회를 기록합니다.**
- 예: 11번 “네가 잡는 줄 알았지”에서 두 수비수 모두 판단 실수를 했다면 선수 개인 기록은 각각 +1, 팀 사건 횟수는 +1입니다.
- **팀의 경기당 최대 10회는 사건 수를 기준으로 적용합니다.** 따라서 선수 개인 횟수의 합과 팀 사건 횟수가 다를 수 있습니다.
- 집계 원칙은 확정입니다. 복잡한 공동 장면에서 책임 선수를 판별하는 세부 조건과 개인·팀 기록의 화면 표시 방식은 추후 정합니다.

#### A-3-2. 개인 기록의 공개와 화면 배치 — 확정

- **개인 기록은 사용자에게 공개합니다.** 선수 관리에서는 전체 누적 기록, 라인업에서는 편성에 필요한 핵심 기록을 보여줍니다.
- 두 화면에서 선수를 선택하면 같은 전체 상세 기록을 확인할 수 있도록 구성합니다.

| 위치 | 표시 내용 | 목적 |
|---|---|---|
| 선수 관리 | 선수를 선택하면 타격·투구·수비·본헤드의 전체 누적 기록을 확인 | 선수의 활약과 실패, 성장 과정을 돌아보고 누구를 키울지 판단 |
| 라인업 | 능력치와 함께 편성에 필요한 핵심 기록 2~3개를 요약. 선수 선택 시 같은 상세 기록을 열 수 있게 구성 | 출전 선수·포지션·타순을 정하면서 기록을 빠르게 참고 |

- **라인업 요약 항목 확정:** 타순 편성에는 타율·출루율, 투수 배치에는 투구 이닝·볼넷, 수비 배치에는 실책·본헤드를 보여줍니다. 관련 능력치와 함께 참고할 수 있게 합니다.
- 기록이 얼마나 쌓였는지 알 수 있도록 경기 수·타석 수·투구 이닝 등 해당 기록의 분량을 함께 보여줍니다.
- 개인 기록 공개, 두 화면의 역할·상세 보기 접근, 라인업 요약 항목과 기록이 없을 때의 표시는 확정입니다. 세부 배치는 추후 정하며 기존 선수 관리·라인업 화면 안에서 구성합니다.

#### A-3-3. 사구·희생플라이와 출루율 집계 — 확정

- **몸에 맞는 공(사구)과 희생플라이를 이번 버전의 경기 및 선수 개인 기록에 포함합니다.** 두 상황의 판정·진루·득점은 일반 야구 규칙을 따릅니다.
- 사구는 타석에 포함하고 타수·안타에는 포함하지 않습니다. 출루율에서는 분자와 분모에 모두 반영합니다.
- 희생플라이는 타석에 포함하고 타수·안타에는 포함하지 않습니다. 공식 판정에 따른 타점을 기록하며 출루율의 분모에 반영합니다.
- **출루율 = (안타 + 볼넷 + 사구) ÷ (타수 + 볼넷 + 사구 + 희생플라이)**. 전체 타석 수로 분모를 임의 대체하지 않습니다. [공식 기록 계산 안내](https://img.mlbstatic.com/milb-images/image/upload/milb/a0bs5d2p8prnsy0i9qms.pdf)
- 타수 등 각 원기록의 포함·제외는 공식 기록 규칙을 따릅니다. 게임에서 발생한 상황에 해당하는 기록을 누락하거나 다른 항목으로 바꾸지 않습니다.
- 규칙과 기록의 포함 여부는 확정입니다. 사구 등의 발생 확률과 장면 표현은 이후 경기 설계에서 조정합니다.

#### A-3-4. 최근 무안타 표시 — 확정

- **마지막 안타 이후의 연속 무안타 타수**를 선수별로 계속 집계합니다. 아직 안타를 기록하지 않은 선수는 첫 타수부터 집계합니다.
- **0~5타수에서는 무안타 멘트를 표시하지 않고, 6타수 연속 무안타에 도달하면 표시합니다.** 이후에도 안타가 없으면 “7타수 연속 무안타”, “8타수 연속 무안타”처럼 실제 누적된 타수를 표시합니다.
- 안타가 나오면 연속 무안타 타수를 0으로 초기화하고 해당 멘트를 해제합니다.
- 볼넷·사구·희생플라이처럼 공식 타수에 포함하지 않는 결과는 무안타 타수를 늘리지도, 연속 기록을 끊지도 않습니다.
- 경기 종료·다음 경기·미출전만으로 연속 기록을 초기화하지 않습니다. 6타수 미만인 상태도 저장하며 재접속 시 그대로 이어집니다.
- 6타수는 **멘트 표시를 시작하는 기준**입니다. 그전의 실제 경기 기록이나 무안타 집계를 생략하는 기준이 아닙니다.
- 목적은 짧은 무안타 구간에서부터 멘트를 반복하지 않고, 부진이 이어졌을 때 사용자의 약이 오르는 상황을 만드는 것입니다. 반응 멘트는 오른쪽 상단의 사건당 한 카드 규칙을 따릅니다. 현재 대사 후보는 I-3의 g23이며, 정확한 등장 빈도·반복 억제 방식은 F-2에 남깁니다.

### A-4. 보유 인원과 영입·방출

- 보유 한도는 15명입니다. 초기 9명에서 영입을 통해 늘어납니다.
- 한도가 찼어도 **신규 선수의 능력치를 먼저 공개**합니다.
- 사용자는 신규 선수를 영입하며 기존 선수 1명을 내보낼지, 기존 선수단을 유지할지 결정합니다.
- 영입을 거절했다고 기존 선수를 강제로 삭제하지 않습니다.
- 기존 선수를 내보낼 때 확인창과 누적 기록이 사라진다는 안내를 표시합니다.
- **확정:** 출전 편성에 있던 선수를 신규 영입 선수로 교체하면 새 선수가 기존 선수의 포지션·타순을 우선 이어받습니다. 경기 전에 사용자가 자유롭게 다시 편성할 수 있습니다.
- 출전 편성에 없던 선수를 교체한 경우에는 기존 출전 선수·포지션·타순을 유지합니다. 이 처리는 경기 사이의 선수 영입에 적용하며 경기 중 선수 교체 기능을 추가하지 않습니다.
- 보유 인원이 15명 미만이어도 영입을 거절하고 15코인을 받을 수 있습니다. 트로피는 유지하며, 한 기회에서 선수와 코인을 중복 수령하지 않습니다. 상세 보상 규칙은 부록 D를 따릅니다.

### A-5. 출전 편성

- 보유 선수 중 9명을 선택하고, 각 선수에게 이번 경기의 포지션과 타순을 배정합니다.
- 포지션: 투수(P), 포수(C), 1루수(1B), 2루수(2B), 3루수(3B), 유격수(SS), 좌익수(LF), 중견수(CF), 우익수(RF).
- 타순: 1~9번을 사용자가 직접 정합니다.
- 선수의 고정 포지션은 없지만 편성한 포지션에서는 해당 역할을 수행합니다.
- 포지션 평가 예: 투수는 구속·제구, 포수는 포구·송구, 유격수는 주력·야구센스·포구·송구, 중견수는 주력·야구센스·포구를 활용합니다.
- **경기 중 선수 교체는 넣지 않습니다.** 경기 전 편성 및 경기 사이의 영입 교체와 구분합니다.

## 부록 B. 경기 진행과 감독 지시 상세

### B-1. 기본 규칙

- **별도로 정한 예외가 없으면 일반 야구 규칙을 따릅니다.** 공·스트라이크·아웃, 타자와 주자의 진루, 득점 및 기록 판정에 같은 원칙을 적용합니다.
- 이 게임에서 별도로 정한 경기 방식은 **5이닝, 최대 7회 연장 후 무승부, 경기 중 선수 교체 없음**입니다. 일반 규칙을 따른다는 이유로 이미 확정한 방식을 바꾸지 않습니다.
- 사용자 팀 대 봇 팀.
- 5이닝, 3아웃 공수 교대.
- 홈·원정은 각각 50% 확률로 결정합니다. 원정은 초 공격, 홈은 말 공격입니다.
- 5회 동점이면 연장하며 최대 7회까지 진행합니다. 7회까지 동점이면 무승부입니다.
- 끝내기를 지원합니다. 승부가 결정된 뒤 불필요한 공격을 계속하거나 추가 보상을 중복 계산하지 않습니다.

### B-2. 반자동·자동·일시정지

- 기본은 반자동 경기입니다. 선수들이 기본 판단으로 플레이하고 사용자는 필요할 때 개입합니다.
- 자동 경기는 공격·수비·전략을 모두 자동 판단하며 더 빠르게 진행합니다.
- 자동 경기 도중 반자동으로 복귀할 수 있습니다. 전환으로 이미 결정한 공의 결과를 다시 뽑지 않습니다.
- 두 모드의 코인·트로피 보상은 같습니다.
- 일시정지 중 화면의 상대 타자 최소 정보·투수 정보와 카운트를 확인하고 전략을 고민할 수 있습니다. 별도 상대 전체 능력치 열람 기능을 추가하는 뜻은 아닙니다.
- 일시정지는 이미 확정한 지시를 취소하는 기능이 아닙니다.
- 반자동의 선택 시간은 최대 5초이며, 사용자가 지시를 고르지 않아도 기본 판단으로 진행합니다. ‘그대로 해’로 대기를 생략할 수 있고 자동 경기에서는 선택 대기를 생략합니다.

### B-3. 공격 지시

| 버튼 | 말투와 의도 | 효과와 대가 |
|---|---|---|
| 풀스윙! | “한 방 노려!” | 파워 활용과 장타 가능성이 늘고 헛스윙 위험도 증가 |
| 컨택! | “맞혀!” | 컨택 활용과 인플레이가 늘고 장타 기대가 감소 |
| 참아! | “좋은 공 아니면 참아!” | 선구안이 중요해지고 볼에 스윙할 가능성이 감소. 볼넷 가능성이 늘지만 스트라이크를 지켜볼 수도 있음 |

- 매 공마다 게임이 기본 판단을 새로 정하고 현재 판단을 화면에 표시합니다.
- 입력이 없으면 기본 판단으로, 입력이 있으면 사용자 지시를 반영해 해당 공을 처리합니다.
- **지시를 내린 해당 공 한 개에만 적용합니다. 이후 공을 위한 예약 기능은 넣지 않습니다.**
- 선택한 지시는 변경·취소할 수 없습니다. 다음 투구 전 초기화합니다. 실수한 지시를 되돌리지 못하는 것도 의도한 재미에 포함됩니다.
- **투수가 공을 던지기 전까지 공격 지시를 입력할 수 있습니다.** 매 공의 선택 준비 구간에 5→4→3→2→1을 표시하며, 공을 던진 뒤에는 새 지시를 받지 않습니다. 입력 마감과 화면에서 공을 놓는 시점은 일관되게 연결합니다.
- **최신 결정은 5초 선택 표시와 ‘그대로 해’ 버튼을 사용하는 것입니다.** 투구 동작과 실제 공 사이 간격은 이 선택 규칙을 유지하면서 세부 조정합니다. 선택만으로 남은 시간이 자동 생략되지는 않습니다.
- 지시는 행동의 경향을 바꿉니다. ‘참아!’를 눌렀어도 선수가 볼에 스윙하는 상황이 가능합니다.
- 풀스윙·컨택·참아라는 버튼만으로 실제 스윙 여부와 타석 결과를 바로 확정하지 않습니다.

### B-4. 수비 지시 — 입력 시점·단위·의도 확정

- 상대 타자가 나올 때 게임이 먼저 수비 깊이와 시프트를 판단해 표시합니다.
- **입력 가능 시점은 상대 타자가 타석에 들어온 뒤부터, 투수가 해당 타석의 첫 공을 던지기 전까지입니다.** 그 사이에 상대 타자 1명당 한 번 원하는 수비를 지시할 수 있습니다.
- 지시는 해당 타석이 끝날 때까지 유지되고, 다음 타자에서 새로 판단합니다. 첫 공을 던진 뒤에는 해당 타석의 새 수비 지시를 받지 않습니다. 첫 투구 전에 입력하지 않았다면 기본 수비 판단을 사용합니다.
- 타석 도중 일시정지하거나 자동 경기에서 반자동으로 바꾸더라도 이미 지난 수비 지시 입력 기회가 다시 열리지는 않습니다.
- **수비 깊이:** 전진 / 기본 / 후퇴.
- **시프트(좌우 수비 위치 이동):** 좌 / 기본 / 우.
- 입력이 없으면 기본 판단으로 진행합니다.
- 지시는 원하는 수비 배치와 행동에 영향을 주지만 실제 수비 성공이나 경기 결과를 보장하지 않습니다.
- **유지되는 것은 지시이며 선수의 위치를 고정하는 것이 아닙니다.** 그라운드에서 선수들이 움직이는 모습을 보고 감독처럼 판단하고 지시하는 경험을 표현합니다.
- 수비 지시 선택 시간은 상대 타자의 **첫 투구 전 한 번만 5초**입니다. 그 타석의 두 번째 공부터는 수비 선택 카운트다운을 반복하지 않습니다.
- 수비 입력의 현 시안은 깊이 3개×좌우 3개를 한 번에 고르는 3×3 배치입니다. 이는 같은 수비 지시를 표현하는 화면 적용안이며 새로운 수비 규칙이 아닙니다.
- 선택과 ‘그대로 해’, 시간 종료의 관계는 B-5를 따릅니다. 선택한 지시를 다시 바꾸거나 취소하는 별도 절차는 넣지 않습니다.
- 선수 이동과 지시 반영의 시각적 방향은 H-4를 따르며, 정확한 이동 시간·카메라 동작은 미정입니다. 공격의 매 공 초기화와 수비의 타석 유지 규칙을 구분합니다.

### B-5. 5초 선택과 ‘그대로 해’ — 최신 결정 통합

| 상태·입력 | 진행 방식 |
|---|---|
| 반자동 공격의 새 공 | 현재 기본 판단과 남은 5초를 보여주고 입력을 받음 |
| 반자동 수비의 상대 새 타자 | 첫 투구 전 기본 수비와 남은 5초를 보여주고 입력을 받음 |
| 지시를 고름 | 해당 지시를 확정 표시하고 변경·취소는 막음. 남은 선택 시간은 계속 표시 |
| 지시 없이 ‘그대로 해’ | 화면에 표시된 기본 판단으로 남은 대기를 생략하고 투구로 진행 |
| 지시를 고른 뒤 ‘그대로 해’ | 선택한 지시를 유지해 남은 대기를 생략하고 투구로 진행 |
| 버튼 없이 5초 종료 | 선택한 지시가 있으면 그 지시, 없으면 기본 판단으로 투구 진행 |
| 자동 경기 | 기본 판단으로 진행하며 5초 선택 대기 없음 |

- ‘그대로 해’는 지시를 취소하거나 기본 판단으로 되돌리는 버튼이 아닙니다.
- 선택이 확정되거나 투구가 시작된 공에 예약·변경·취소를 추가하지 않습니다. 수비 지시는 그 타석 전체에 유지합니다.
- 공을 놓는 장면, 카운트다운 종료와 입력 잠금이 서로 어긋나 보이지 않게 연결해야 합니다. 이 원칙을 만족하는 투구 동작의 세부 시간은 구현 전 조정합니다.
- 일시정지 중 경기 시간은 멈추고, 재개로 이미 고른 지시나 지나간 입력 기회를 되돌리지 않습니다. 선택 도중 새로고침했을 때 남은 시간·선택 상태의 복원 세부 처리는 F-2의 미정 항목이며 E-2의 판정 경계 보존 원칙을 지킵니다.

## 부록 C. 확률 판정·주루·실책·코미디 상세

### C-1. 투구에서 타구까지

기본 타격 흐름: 투구 → 볼·스트라이크 영역 → 타자의 스윙 여부 → 컨택 여부 → 헛스윙·파울·인플레이 → 타구·수비·주루 결과

사구 등 타구가 생기지 않고 타석이 끝나는 상황은 해당 규칙에 따라 별도로 판정합니다.

- 관련 요소: 컨택, 파워, 선구안, 구속, 제구, 공격 지시, 볼카운트, 확률.
- 4볼은 볼넷, 3스트라이크는 삼진으로 기록합니다. 타자·주자의 아웃과 출루 처리는 해당 상황의 일반 야구 규칙을 따릅니다.
- 일반 파울은 2스트라이크 전에는 스트라이크를 늘리고, 2스트라이크 이후에는 카운트를 유지합니다. 번트 파울·파울팁 등 별도 규칙이 있는 상황과 구분합니다.
- **사구를 포함합니다.** 타자의 몸에 맞았다는 사실만으로 출루를 확정하지 않고, 스윙·스트라이크 여부 등 공식 사구 판정을 적용합니다. [사구 판정 참고](https://www.mlb.com/glossary/standard-stats/hit-by-pitch)
- **희생플라이를 포함합니다.** 뜬공 이후의 정상적인 귀루·진루·득점 판정과 연결하며, 공식 기록 규칙에 해당하면 희생플라이로 집계합니다. [희생플라이 참고](https://www.mlb.com/glossary/standard-stats/sacrifice-fly)
- 실제로 스윙하지 않았는데 파울이 되는 등 논리적으로 불가능한 연결은 금지합니다.
- 타구의 기본 결과: 아웃, 1루타, 2루타, 3루타, 홈런. 여기에 수비·주루·실책·본헤드와 병살 판정을 연결합니다.
- 수비 위치와 능력치가 실제 성공·실패에 반영되어야 합니다. 결과 설명 역시 적용한 판정 원인과 맞아야 합니다.

### C-2. 기본 주루·추가 진루·도루

- **1루타·2루타·3루타는 타자에게 기록되는 안타 종류이며, 이미 베이스에 있는 주자의 이동 거리는 따로 판정합니다.** 주자는 타구 상황·주력·수비 결과에 따라 진루하거나 멈추고, 시도에 실패하면 아웃될 수 있습니다.
- 예: 타자가 1루타를 쳐도 2루에 있던 주자는 홈까지 들어올 수 있습니다. 안타 종류에 맞춰 모든 주자를 일괄적으로 같은 칸 수만큼 이동시키지 않습니다.
- 홈런은 타자와 모든 주자가 득점합니다.
- 볼넷은 강제 진루 상황에 맞게 주자를 이동시킵니다.
- 주력에 따라 1루에서 3루, 2루에서 홈 같은 추가 진루가 가능합니다. **주력은 실제로 한 베이스를 더 얻거나 아웃되는 결과에 영향을 주는 능력치**입니다.
- **추가 진루는 선수가 자동으로 판단합니다.** 주자의 주력, 타구 위치, 수비수의 송구 능력 등으로 성공 가능성과 상황을 보고 시도하며, 실패해 아웃될 수 있습니다.
- **도루는 경기 중 주자가 상황을 보고 가끔 스스로 시도하는 이벤트형 방식**입니다. 주자의 주력과 포수의 송구 능력 등이 성공 여부에 영향을 주고, 성공하면 다음 베이스로 진루하며 실패하면 아웃될 수 있습니다.
- 자동 도루 자체를 본헤드로 집계하지 않습니다. 명백히 불리한 상황에서 무모하게 출발하는 판단 실수 등 C-5의 본헤드와 구분합니다.
- 직접 주루 지시는 향후 확장 아이디어이며 이번 버전은 자동 판단을 사용합니다.
- 추가 진루·도루의 세부 발생 조건과 확률, 여러 사건이 겹칠 때 적용 순서는 상세 설계에서 정합니다.

### C-3. 병살 — 두 유형과 주자 처리 원칙 확정

- **한 플레이에서 실제로 두 명이 아웃되는 병살을 포함합니다.**

| 유형 | 상황과 결과 |
|---|---|
| 땅볼 병살 | 땅볼을 처리해 주자와 타자를 연속으로 아웃시킵니다. 예: 2루에서 주자를 아웃시키고 1루에서 타자를 아웃시킴 |
| 뜬공·직선타 포구 후 귀루 실패 병살 | 타구가 잡혀 타자가 아웃되고, 원래 베이스로 돌아가지 못한 주자도 아웃됩니다. 귀루는 원래 베이스로 돌아가는 행동입니다. |

- 아웃된 주자와 타자를 경기 상태에서 정확히 처리하며, 총 아웃 수를 3개를 넘겨 세지 않습니다.
- 위 두 유형은 타자의 타석이 끝나므로 타순은 한 칸 진행합니다.
- 병살에 관여하지 않은 다른 주자도 상황에 따라 진루할 수 있습니다. **진루와 득점 인정은 일반 야구 규칙을 따릅니다.**
- 득점은 세 번째 아웃의 종류와 정상적으로 홈에 도달한 시점을 구분해 판단합니다.

| 검증 상황 | 기대 결과 |
|---|---|
| 1아웃·1루 주자에서 땅볼 병살 | 3아웃으로 공수 교대 |
| 무사·1·3루에서 2루→1루 땅볼 병살 | 2아웃이 되며, 3루 주자가 정상적으로 홈에 도달하면 득점 가능 |
| 1아웃·1·3루에서 2루→1루 땅볼 병살 | 타자가 1루에 도달하기 전 세 번째 아웃이 되므로 해당 플레이의 득점 불인정 |

위 득점 기준은 [공식 야구 규칙 5.08](https://img.mlbstatic.com/mlb-images/image/upload/mlb/ub08blsefk8wkkd2oemz.pdf)을 따릅니다. 병살 발생 확률과 세부 판정 수치는 추후 조정합니다.

### C-4. 수비와 실책

| 판단 단계 또는 사건 | 주로 관련된 능력 | 구분 기준 |
|---|---|---|
| 타구 위치에 도달 | 주력 | 공이 있는 곳까지 갈 수 있는지 |
| 어려운 타구 판단 | 야구센스 | 애매하거나 불규칙한 타구를 처리할 수 있는지 |
| 도달한 공을 잡음 | 포구 | 포구에 성공하는지 |
| 잡은 뒤 던짐 | 송구 | 정확한 송구와 진루 저지에 성공하는지 |
| 폭투 | 제구 | 투수가 포수가 잡기 어려운 공을 던짐. 주자가 있으면 추가 진루 가능 |
| 포일 | 포수의 포구 | 포수가 잡을 수 있는 공을 놓침. 주자가 있으면 추가 진루 가능 |

- 어려운 타구 처리 실패, 포구 실책, 악송구, 폭투, 포일을 원인에 맞게 구분합니다.
- 경기 기록상 안타·실책의 구분과 책임 귀속도 일반 야구의 공식 기록 규칙을 따릅니다. 일반적인 수비로 처리할 수 있었는지를 기준으로 판단하며, 단순히 아웃에 실패했다고 모두 실책으로 기록하지 않습니다. [일반적인 수비 노력의 기준](https://www.mlb.com/glossary/rules/ordinary-effort)
- 비슷한 결과라도 투수와 포수에게 같은 책임을 기록하지 않습니다. 경기 장면을 이 기준에 연결하는 세부 판정 방식은 구현 전에 구체화합니다.
- **확정:** 폭투는 투수의 폭투 기록, 포일은 포수의 포일 기록으로 각각 집계하며, 그 폭투·포일 자체를 실책 합계에 추가하지 않습니다. [공식 야구 기록 규칙 9.12(f)·9.13](https://img.mlbstatic.com/mlb-images/image/upload/mlb/atcjzj9j7wrgvsm8wnjq.pdf)을 따릅니다.

### C-5. 본헤드

#### C-5-1. 발생 원칙과 횟수 — 확정

- 본헤드는 **판단 자체가 엉뚱한 행동**입니다. 단순 포구 실패, 악송구, 폭투 등은 원인에 맞게 구분합니다.
- 현재 주자·아웃·타구 상황에서 가능한 사건만 발생하며, 실제 경기 결과를 바꿉니다.
- 사용자 팀과 상대 팀 모두 본헤드가 발생할 수 있습니다.
- **우리 팀 기준 경기당 기본 1~3회는 선수 성장과 관계없이 매 경기 유지합니다.** 선수 능력은 추가 발생분에 영향을 주며, 능력치가 좋아지면 추가 발생분이 줄어듭니다.
- **모든 능력치가 100인 선수도 본헤드를 할 수 있습니다.** 그런 선수도 기본 본헤드의 대상이 될 수 있습니다. 기본 1~3회는 우리 팀 합계이며 선수마다 발생해야 하는 횟수가 아닙니다.
- **우리 팀은 한 경기에서 기본 발생과 추가 발생을 합쳐 최대 10회**까지 발생합니다. 연장도 같은 경기의 횟수에 포함합니다.
- 상대 팀의 기본 빈도와 상한은 아직 정하지 않았습니다.
- 기본 1회·2회·3회의 분포와 발생 시점, 추가 발생 확률식, 기본 본헤드의 선수 선택 방식은 추후 조정합니다. 여러 선수가 관여한 한 사건은 팀 +1, 실제 판단 실수를 한 선수 각각 개인 +1로 집계하며 A-3-1의 확정 기준을 따릅니다.

#### C-5-2. 본헤드 12종과 연결 능력치

아래 목록은 **야구센스 명칭 변경, 1·2번의 선구안 추가, 12종 모두에 야구센스 70% 공통 적용**을 반영한 확정 목록입니다. 4·6번도 야구센스와 주력을 함께 참조합니다. 구체적인 비중은 C-5-3을 따릅니다.

| 번호 | 본헤드 | 행동과 가능한 경기 영향 | 연결 능력치 |
|---|---|---|---|
| 1 | 홈런인 줄 알고 구경 | 담장 안에 떨어지는 타구를 홈런으로 착각해 천천히 뜀. 장타 기회를 잃거나 뒤늦은 진루로 아웃 가능 | 컨택, 선구안, 야구센스, 주력 |
| 2 | 정상 타구를 파울로 착각 | 페어 판정인데도 파울이라고 생각해 1루로 뛰지 않음. 출루 기회를 잃음 | 컨택, 선구안, 야구센스, 주력 |
| 3 | 잡혔는데 계속 뛰기 | 뜬공이 잡혔는데 귀루를 잊고 계속 진루함. 귀루 실패 병살로 이어질 수 있음 | 컨택, 야구센스, 주력 |
| 4 | 베이스를 안 밟고 지나가기 | 베이스를 빼먹고 다음 베이스로 뜀. 되돌아가느라 시간을 잃거나 수비의 어필로 아웃 가능 | 야구센스, 주력 |
| 5 | 한 베이스에 두 주자 모이기 | 앞 주자가 멈춰 있는데 뒤 주자가 같은 베이스까지 진루함. 움직임이 꼬여 한 명이 아웃될 수 있음 | 야구센스, 주력 |
| 6 | 뛰면 안 될 때 갑자기 도루 | 포수가 공을 들고 자신을 보고 있는데 출발하는 등 명백히 불리한 상황에서 도루함. 아웃 위험 증가 | 야구센스, 주력 |
| 7 | 아웃카운트 착각 | 아직 2아웃인데 공수 교대라고 생각해 공을 들고 더그아웃 쪽으로 이동함. 상대 추가 진루 가능 | 야구센스, 선구안 |
| 8 | 엉뚱한 베이스로 송구 | 주자를 잡을 수 있는 베이스 대신 주자도 없는 곳으로 던짐. 아웃 기회를 잃거나 실점 가능 | 야구센스, 송구 |
| 9 | 태그를 깜빡함 | 주자를 공으로 터치해야 하는 상황에서 베이스만 밟고 안심함. 상대 주자가 살아남음 | 야구센스, 포구 |
| 10 | 수비 성공에 취해 세리머니 | 포구 직후 송구해야 하는데 세리머니로 지연함. 병살 기회를 놓치거나 상대가 추가 진루 | 야구센스, 송구 |
| 11 | “네가 잡는 줄 알았지” | 두 수비수가 서로 상대가 잡을 것으로 생각해 멈춤. 사이로 타구가 떨어져 상대 출루·진루 가능 | 야구센스, 선구안 |
| 12 | 베이스 들어가는 걸 깜빡함 | 송구를 받으러 베이스에 들어가야 할 선수가 제자리에 있음. 동료가 던질 곳을 잃어 아웃 기회를 놓침 | 야구센스, 주력 |

- 4번의 어필은 수비가 베이스를 밟지 않은 사실을 지적하며 아웃 판정을 요청하는 행동입니다. [베이스 누락과 어필 규칙](https://www.mlb.com/glossary/rules/appeal-plays)을 따릅니다.
- 9번은 베이스만 밟아서는 아웃되지 않고 주자를 터치해야 하는 상황에 해당합니다. [강제 진루와 태그 규칙](https://www.mlb.com/glossary/rules/force-play)을 따릅니다.
- 일반적인 추가 진루 실패나 정상적인 도루 실패를 모두 본헤드로 바꾸지 않습니다. 위와 같은 판단 실수의 행동과 원인이 드러나야 합니다.
- 12종의 장면 흐름은 H-5, 현재 대사 후보는 I-3의 b01~b12에 통합했습니다. 실제 발생 조건·확률·책임 판별·기록 분류·효과의 크기와 동작의 세부 시간은 계속 조정이 필요합니다.

#### C-5-3. 본헤드 능력치 비중 — 확정

- **확정:** 본헤드 발생을 판단하는 능력치 계산에서 야구센스의 비중을 **70%**로 둡니다. 이는 실제 본헤드가 70% 확률로 발생한다는 뜻이 아닙니다.
- **확정:** 12종 모두 야구센스를 70%로 공통 적용하고, 나머지 30%를 해당 항목의 다른 연결 능력치에 동일하게 나눕니다. 4·6번에도 야구센스 70%와 주력 30%를 적용합니다.

| 본헤드 번호 | 야구센스 비중 | 나머지 30% 비중 |
|---|---|---|
| 1·2 | 70% | 컨택 10% + 선구안 10% + 주력 10% |
| 3 | 70% | 컨택 15% + 주력 15% |
| 4·5·6·12 | 70% | 주력 30% |
| 7·11 | 70% | 선구안 30% |
| 8·10 | 70% | 송구 30% |
| 9 | 70% | 포구 30% |

- 위 비중으로 구한 능력치 점수가 낮을수록 해당 본헤드의 추가 발생 가능성이 높아지는 방향입니다. 예를 들어 8번의 판정용 능력치 점수는 ‘야구센스×0.7 + 송구×0.3’입니다. 능력치가 높아져도 기본 1~3회가 사라지지는 않습니다.
- 이 점수는 실제 발생 확률과 별개입니다. 점수를 발생 확률·추가 발생 횟수에 연결하는 식, 여러 선수가 관여할 때 판정에 참조할 선수, 서로 다른 사건이 동시에 일어날 때의 처리 순서는 미정입니다. 발생한 공동 사건의 개인·팀 횟수 집계는 A-3-1을 따릅니다.
- 야구센스의 선수 뽑기 상한은 70, 훈련 상한은 100입니다. 뽑기에서 곧바로 야구센스 100이 나오지 않습니다.

### C-6. 코미디와 결과 설명

| 화자·장치 | 통합 방향 |
|---|---|
| 중계진 | 사실을 담담하게 설명한 뒤 짧게 지적하는 말투 |
| 우리 팀 치어리더 | 응원 속에 핀잔을 섞으며 우리 홈런에는 크게 축하 |
| 상대 팀 치어리더 | 밝고 예의 바른 말투로 약을 올림 |
| 상대 팀 관객 | 직설적이고 편파적인 놀림 |
| 우리 팀 관객 | 화를 내면서도 계속 보는 애증, 좋은 플레이에는 큰 환호 |
| 굴욕 기록 | 연속 무안타는6타수 이상부터 사용. 실제 헛스윙·병살·본헤드 기록과 연결 |
| 낚시 중계·판단 개그 | “크게 뻗습니다! …평범한 외야 플라이.”, “선수 본인의 판단이었습니다.” 같은 기존 표현 방향. 사용할 경우 한 사건의 같은 화자 카드 안에서 처리 |
| 영입·결과 | 뜻밖의 능력치와 패배 뒤 재도전에서 웃음을 만듦 |

- **사건 하나당 화자 카드 하나만** 오른쪽 상단에 나타났다가 사라집니다. 상황별3~4개 후보 중 무작위로 하나를 사용하며, 현재 작성된 목록은42상황×4개=168개입니다.
- 본헤드로 아웃되는 등 한 사건의 원인과 결과가 함께 있어도 각각의 반응을 연달아 띄우지 않습니다. 선택 적용안은 부록 I에 정리합니다.
- 중요한 결과에는 짧은 이유를 제공합니다. 폭투는 제구, 포일은 포구, 어려운 타구 판단은 야구센스 등 실제 적용한 원인과 맞춰 누구를 성장시킬지 이해할 수 있게 합니다.
- 성향이나 사용자의 지시만으로 성공·실패를 단정하는 대사를 먼저 출력하지 않습니다. 대사는 경기 판정이나 보상을 바꾸지 않습니다.
- 전체 화자별 말투는 사용자 동의를 받은 방향입니다. 개별 문구는 검토용 후보로 I-3에 수록하며, 낚시 중계 등 이 표의 기존 표현 예시는168개 목록 밖의 표현 참고안입니다.
- 상황별·화자별3~4개로 대사를 더 늘리는 것은 이번에 확정한 **향후 확장 방향**이며, 마지막 부록 K에 둡니다.

## 부록 D. 성장·보상·상대 난이도 상세

### D-1. 코인 — 확정

- **경기 완료 코인 = 기본 1코인 + 내 팀 득점**입니다.
- 승리·패배·무승부와 자동·반자동에 같은 산식을 적용합니다.
- 완료 보상은 경기당 한 번만 지급합니다. 결과 화면 재방문이나 재접속으로 중복 지급하지 않습니다.

| 경기 결과 예시 | 경기 완료 코인 |
|---|---|
| 0:3 패배 | 1코인 |
| 2:0 승리 | 3코인 |
| 8:9 패배 | 9코인 |

영입 거절로 받는 15코인은 이 경기 완료 보상에 별도로 더해지는 보상입니다.

### D-2. 트로피와 영입 간격 — 확정

- **매 승리마다 트로피 +1과 신규 랜덤 선수 영입 기회 1회**를 제공합니다. 첫 승부터 적용합니다.
- 트로피는 소모 재화가 아니라 누적 진행도입니다. 영입 또는 영입 거절로 차감하지 않습니다.
- 패배·무승부에 대한 별도의 추가 트로피 보상은 정하지 않았습니다.
- 선수의 능력치를 공개한 뒤 사용자가 영입 여부를 선택합니다. **선수 영입 또는 영입 거절 보상 15코인 수령을 완료해야 해당 저장칸의 다음 경기를 시작할 수 있습니다.** 결정을 미루거나 영입 기회를 쌓아 두고 다음 경기를 진행하지 않습니다.
- 선택 중 창을 닫았다면 재접속 시 동일한 영입 선수와 선택 대기 상태를 복구합니다. 같은 기회를 다시 뽑거나 이미 받은 보상을 중복 지급하지 않습니다.
- 의도: 승리 → 선수 확인 → 영입 또는 기존 선수 훈련 → 다음 경기로 이어지는 보상을 자주 경험하게 합니다.

### D-3. 영입 거절 — 확정

- 신규 선수의 능력치를 확인한 뒤 **영입을 거절하면 선수 대신 15코인**을 받습니다.
- **선수단에 빈자리가 있어도 거절할 수 있습니다.**
- 누적 트로피는 유지합니다.
- 한 영입 기회에서 신규 선수 또는 15코인 중 하나만 받으며, 처리 완료 상태를 저장합니다. **미결정 상태에서는 다음 경기를 시작할 수 없습니다.** 영입을 선택했다면 필요한 기존 선수 교체까지 완료하고, 거절했다면 15코인 지급까지 완료한 뒤 진행합니다.
- 보유 선수가 15명일 때 영입을 선택하면 기존 선수 1명과 교체합니다. 교체할 선수의 기록이 사라진다는 안내와 확인은 A-4를 따릅니다.

### D-4. 선수 성장 — 비용표 확정

- 코인을 사용해 원하는 선수의 원하는 능력치를 **+1** 합니다.
- 비용은 **성장시키기 전의 현재 능력치**에 따라 아래 표를 적용합니다.

| 현재 능력치 | +1 성장 비용 |
|---|---|
| 1~49 | 1코인 |
| 50~64 | 2코인 |
| 65~79 | 3코인 |
| 80~89 | 4코인 |
| 90~94 | 6코인 |
| 95~99 | 8코인 |
| 100 | 추가 성장 불가 |

- 예: 49→50은 1코인, 50→51은 2코인, 99→100은 8코인입니다.
- **훈련 상한은 모든 능력치 100**입니다. 야구센스도 훈련으로 100까지 성장할 수 있으며, 선수 뽑기 상한 70과 구분합니다.
- 코인이 부족하거나 이미 100이면 코인을 차감하지 않고 성장할 수 없는 이유를 표시합니다.
- 모든 선수가 장기적으로 올 100이 되는 상황을 막기 위한 새로운 제한·은퇴·강제 이적은 이번 범위에 추가하지 않습니다. MLB 진출은 향후 확장으로 남깁니다.

### D-5. 상대 난이도 — 구간 확정, 전력 수치 미정

- 처음에는 이길 만한 상대를 만나고, **누적 5승마다 상대 팀의 기본 수준을 조금씩 높입니다.**
- 현재 승리 트로피는 승리당 +1이므로 누적 승리와 같은 진행 기준입니다.

| 누적 승리 | 상대 기본 수준의 구간 |
|---|---|
| 0~4승 | 시작 구간 |
| 5~9승 | 다음 구간 |
| 10~14승 | 그다음 구간 |
| 이후 | 5승 단위로 구간 상승 |

- 같은 구간에서도 약팀과 강팀이 무작위로 등장합니다.
- 사용자 능력에 완전히 맞춰 상대 전력을 조정하지 않습니다. 영입과 훈련으로 강해진 효과를 느낄 여유를 줍니다.
- 영입 기회는 매 승리, 상대 기본 수준 상승은 5승마다 적용합니다.
- 초기 상대 능력치 분포, 구간별 전력 상승 폭, 장기 수치와 상한은 향후 조정합니다.

## 부록 E. 저장·복구·데이터 관리 상세

### E-1. 자동 저장 대상

아래 데이터는 **저장칸 1번·2번의 각 게임에 따로 보관**합니다. 자동 저장은 현재 플레이 중인 저장칸에 적용하며, 다른 저장칸의 선수·코인·기록·진행 상태와 섞이지 않습니다.

- 팀 이름, 유니폼 주 색상·부 색상과 관련 외형 설정.
- 보유 선수, 이름·등번호, 좌우타와 타구 성향, 능력치, 누적 기록.
- 코인, 트로피, 승패와 무승부 기록, 경기 보상 수령 상태, 신규 영입 기회, 공개한 영입 선수 정보, 선수·15코인 선택의 대기·처리 완료 상태.
- 출전 선수, 포지션, 타순.
- 경기 진행 상태: 상대 팀, 홈·원정, 이닝, 카운트, 아웃, 주자, 타순 진행, 현재 타자·투수, 점수와 경기 기록, 해당 경기의 본헤드 누적 횟수.
- 현재 지시 적용 상태, 자동·반자동 모드와 일시정지 상태 등 정확한 복구에 필요한 정보.
- 봇 유니폼 배색, 양 팀 타순의 현재·마지막 완료·다음 타자 표시에 필요한 진행 정보. 같은 저장 상태에서 선수·치어리더·관객의 팀색이 달라지지 않아야 합니다.
- 한 사건의 반응이 중복 표시되지 않도록 판정 완료와 반응 처리 상태를 일관되게 관리하는 적용안. 세부 저장 항목은 구현 전에 정합니다.

### E-2. 창 닫기·새로고침 후 복구 — 확정

- 경기 중 창을 닫거나 새로고침하고 다시 열면 **마지막으로 판정이 끝난 공 이후 상태에서 이어갑니다.**
- 이미 끝난 공의 판정을 다시 뽑거나, 같은 득점·아웃·기록을 다시 더하지 않습니다.
- 타석·공수 교대가 남아 있으면 정확히 한 번 처리해야 합니다.
- 경기 완료 보상은 해당 경기에 한 번만 지급하며, 결과 화면을 다시 보거나 재접속했다고 다시 지급하지 않습니다.
- 자동 경기 중 복구했을 때도 원래 상태와 판정 경계를 지켜야 합니다.
- **재개 동선 확정:** 메인에서 이어갈 저장칸의 ‘이어하기’를 선택하고 불러오기 확인창에서 확인하면, 해당 칸에 저장된 경기 화면을 정지 상태로 보여줍니다. 사용자가 ‘경기 재개’를 눌렀을 때 진행합니다. 진행 중인 경기가 없는 저장칸은 해당 팀의 메인 상태를 불러옵니다.
- 중단 전에 자동 경기였더라도 ‘경기 재개’를 누르기 전에는 공을 진행하지 않습니다. 재개 시 기존 모드와 이미 확정된 지시·경기 상태를 유지합니다.

### E-3. 저장 형식과 사용자 구분

- 저장 데이터에 `saveVersion: 1`을 포함합니다. 이는 데이터 형식의 버전 번호이며 사용자를 구분하는 값이 아닙니다.
- 향후 업데이트로 필드가 추가되면 기본값을 적용하는 등 기존 저장 자료를 읽는 방법을 마련합니다.
- 각 사용자의 데이터는 각자 사용하는 브라우저의 `localStorage`에 **최대 2개의 게임 진행**으로 저장합니다. 저장칸 1·2의 데이터와 현재 선택한 저장칸을 구분해 보관합니다.
- 같은 PC·브라우저·프로필·사이트를 공유하면 같은 저장소를 사용할 수 있습니다. 서로 다른 기기 사이의 자동 동기화는 포함하지 않습니다.

### E-4. 저장칸 2개·백업·불러오기·초기화 — 확정

#### E-4-1. 저장칸과 새 게임

- **게임 안에서 서로 다른 팀과 진행을 저장하는 칸은 1번·2번, 총 2개입니다.** 각 칸의 선수·성장·코인·트로피·승패·개인 기록·진행 중인 경기·보상 수령 상태는 독립적으로 유지합니다.
- 저장된 게임이 0개 또는 1개라면 빈 저장칸에 새 게임을 만들 수 있습니다. 기존 게임은 그대로 보관합니다.
- **두 칸이 모두 차 있으면 세 번째 저장칸을 만들지 않습니다.** 사용자가 기존 두 게임 중 지울 하나를 선택하고, 삭제 확인 후 그 자리에 새 게임을 만듭니다. 게임이 임의로 삭제 대상을 정하지 않습니다.
- 새 게임은 최초 설정과 초기 선수 9명 생성부터 시작합니다. 기존 다른 저장칸의 자원·선수·기록을 가져오지 않습니다.

#### E-4-2. 보관과 불러오기

- **자동 저장·이어하기:** 현재 플레이 중인 저장칸의 진행을 저장합니다. 메인에서 저장칸을 골라 불러오며, 진행 중인 경기는 E-2에 따라 정지 상태에서 재개를 기다립니다.
- **저장 파일 내려받기(백업):** 선택한 저장칸 하나의 현재 상태를 복사본 파일로 PC에 보관합니다. 백업을 내려받아도 게임 안에 새 저장칸이 생기지 않습니다.
- **백업 파일 불러오기:** 저장 파일을 가져올 칸을 선택하고 확인한 뒤, 그 파일을 저장했던 시점의 팀·진행 상태를 해당 칸에 복원합니다. 빈 칸을 사용하거나, 이미 찬 칸을 선택해 기존 내용을 대체합니다. 파일을 가져와도 게임 안의 저장칸 상한은 2개입니다.
- 게임 안의 저장칸 불러오기는 그 팀으로 전환하는 동작이며 다른 칸의 내용을 대체하지 않습니다. 백업 파일 불러오기는 선택한 칸에 파일의 내용을 복원하는 동작입니다.
- 파일은 JSON 형식으로 내보내고 불러옵니다. JSON은 게임 데이터를 파일로 담는 형식입니다. 필수 항목·숫자 범위·자료 구조를 검사하고, 허용한 누락 항목에는 기본값을 적용합니다. 잘못된 파일을 불러오는 데 실패하면 기존 저장은 유지합니다.

#### E-4-3. 삭제·처음부터 다시 하기와 확인창

- **처음부터 다시 하기:** 사용자가 선택한 저장칸의 팀·진행 기록을 지우고 그 칸에서 새 팀을 시작합니다.
- **저장 삭제:** 선택한 저장칸의 게임을 지워 빈 칸으로 만듭니다. 다른 저장칸은 유지합니다.
- **불러오기·삭제·처음부터 다시 하기는 실행 전에 확인창을 보여줍니다.** 어떤 저장칸·팀이 대상인지, 기존 내용이 바뀌거나 지워지는지를 해당 행동에 맞게 표시합니다.
- 사용자가 취소하면 전환·삭제·초기화를 실행하지 않고 기존 게임을 유지합니다. 한 칸을 불러오거나 지우거나 초기화해도 다른 칸의 데이터와 보상 상태는 바뀌지 않습니다.

### E-5. 보관하지 않는 정보

- 비밀번호, 외부 서비스 인증값(API 키), 인증 토큰, 민감 개인정보를 저장하지 않습니다.
- 게임 서버, 서버 데이터베이스, 외부 생성형 AI API는 사용하지 않는 기획입니다.

- 양옆에 각각 9명 타순을 보여주고 공격팀의 현재 타자, 수비팀의 마지막 완료 타석·다음 타자를 실제 상태와 맞춤. 병살·공수 교대·처음 시작·저장 복구 시에도 표시가 맞음.
- 각 팀 목록 아래 현재 타자·투수 정보가 맞게 바뀜. 수비 중 상대 타자의 판단 정보는 좌타/우타·타구 성향·파워이며 불필요한 전체 기록이 추가되지 않음.
- 주·부 색상에서 같은 14색 목록을 사용하고 봇 유니폼과 구별됨. 두 팀 각각 선수·치어리더·관객의 유니폼이 일치하며 상대 변경·저장 복구에도 유지됨.
- 모든 본헤드 12종과 일반 플레이의 실제 공·선수 동작이 판정과 연결됨. 정지 시안의 순서 설명용 칸을 별도 경기창으로 구현하지 않음.
- 홈런은 크게 축하하고 올바른 베이스 순회와 인정된 득점을 보여줌. 큰 효과나 반응 카드가 주요 조작·정보를 가리지 않음.
- 현재 목록의 42개 상황마다 후보 4개가 연결돼 총 168개이며, 선택한 문구의 화자·소속 팀이 함께 맞게 표시됨. 상황별·화자별 추가 문구를 현재 이미 작성한 것으로 처리하지 않음.
- 반응 대상 사건당 카드 하나만 나타났다가 사라짐. 본헤드와 아웃, 도루 실패와 도루 저지, 끝내기 홈런과 승리처럼 같은 사건의 결과가 겹쳐도 카드를 중복 표시하지 않음.
- 연속 무안타 문구의 실제 타수와 6타수 이상 조건이 맞으며 다른 타석 반응과 중복되지 않음. 새로고침·결과 화면 진입으로 같은 사건의 반응이나 보상이 중복 처리되지 않음.

## 부록 H. 화면 디자인·팀 유니폼·경기 움직임

### H-1. 시각적 방향과 화면 상태

- PC 중심의 2D 픽셀 야구 게임입니다. 사용자가 제공한 참고 이미지의 밝은 야구장, 작은 선수 캐릭터, 남색 패널·밝은 파란 테두리·노란 주요 버튼을 시각적 기준으로 삼습니다.
- 화면의 정보는 읽기 쉽게 정리하고, 웃음은 선수 행동·표정·대사에서 만듭니다. 팀 색상이 바뀌어도 기본 메뉴의 남색 계열은 유지하는 시안입니다.
- 기본 8개 화면은 5-2를 따릅니다. 시안에서는 저장 선택/메인, 최초 설정, 선수 관리, 편성, 공격/수비 경기, 성장, 영입/만석 교체, 승리/패배/무승부 결과와 보조 상태를 나눠 보여줬습니다.
- 필요한 보조 상태는 불러오기 확인, 저장칸 만석, 삭제·처음부터 다시 하기 확인, 일시정지·이어하기, 입력 누락·코인 부족·저장 오류 안내입니다. 확인창의 실제 처리 규칙은 A·D·E를 따릅니다.
- 현재 시안은 움직임의 순서를 설명하는 정지 이미지입니다. 실제 동작이나 무작위 표시가 구현된 결과가 아닙니다. 참고 이미지는 J-1에 연결했습니다.

### H-2. 경기 화면의 두 팀 타순과 현재 선수 정보

**확정 요구:** 그라운드 양옆에 우리 팀과 상대 팀의 9명 타순을 작게라도 계속 보여주고, 현재 타순과 수비 팀의 마지막 타석 진행 위치를 표시합니다. 각 목록 아래에는 해당 팀의 현재 타자 또는 투수 정보를 둡니다.

| 위치 | 현재 시안 적용안 |
|---|---|
| 왼쪽 | 우리 팀 9명 타순. 공격/수비가 바뀌어도 팀 위치는 고정 |
| 오른쪽 | 상대 팀 9명 타순. 공격/수비가 바뀌어도 팀 위치는 고정 |
| 공격 팀 목록 | 현재 타자를 노란 행과 ‘타석’으로 강조 |
| 수비 팀 목록 | 마지막으로 완료한 타석에 ‘마지막’, 다음 공격에서 나올 타자에 ‘다음’ 표시 |
| 각 목록 아래 | 공격 팀은 현재 타자, 수비 팀은 현재 투수의 정보 카드 |
| 중앙 상단 | 점수·이닝·볼/스트라이크/아웃·주자 상태 |
| 중앙 하단 | 공격 3개 지시 또는 수비 3×3 선택, 남은 시간과 ‘그대로 해’ |
| 그라운드 내부 오른쪽 상단 | 반응 인물과 말풍선. 상대 타순·투수/타자 카드·주요 경기 동작과 겹치지 않게 배치 |

- 두 팀 모두 9개 포지션·1~9번 타순을 사용합니다. 시안에 지명타자(DH)나 경기 중 교체 버튼을 추가하지 않습니다.
- **수비 중 상대 타자 정보는 이름/타순 식별 외에 좌타·우타, 당겨치기·중앙·밀어치기 성향, 파워만 표시**합니다. 상대 타자의 컨택·선구안·주력·당일 기록을 이 카드에 늘려 넣지 않습니다.
- 우리 공격 타자 카드의 현재 표시안은 컨택·파워·선구안, 현재 투수 카드는 구속·제구·야구센스입니다. 이 세부 조합은 시안 적용안이며 전체 개인 기록 화면을 대신하지 않습니다.
- ‘마지막’은 마지막으로 완료한 타석, ‘다음’은 다음에 타석에 들어올 타자를 뜻합니다. 아직 타석이 없으면 마지막 타자는 비어 있는 상태로, 다음 타자는 1번으로 표시하는 초기 적용안입니다.
- 병살로 두 명이 아웃돼도 끝난 타석은 하나이므로 타순을 두 칸 넘기지 않습니다. 경기 상태가 바뀔 때 양쪽 목록·카드·점수가 함께 갱신돼야 합니다.
- 초기 제안의 ‘상대 타자 카드를 우리 투수 카드 위에 배치’는 최신 양옆 타순 아래 카드 구성으로 대체합니다.
- 좌우 타구 방향은 A-1을 따릅니다. 홈에서 중견수 방향으로 보는 화면에서 우타자의 당겨치기는 좌측, 좌타자는 우측이며, 성향과 지시가 모든 결과를 고정하지 않습니다.

### H-3. 자유 배색과 양 팀 인물의 동일 유니폼

**확정 요구:** KBO 구단별 고정 조합 대신, 주 색상과 부 색상을 같은 목록에서 각각 자유롭게 선택합니다. 사용자 팀과 봇 팀은 경기에서 구별되는 유니폼을 사용합니다.

**현재 공통 선택지 14색:** 검정, 진홍, 빨강, 흰색, 남색, 아이보리, 파랑, 금색, 주황, 짙은 와인색, 노랑, 초록, 분홍, 보라.

| 구분 | 현 시안의 적용 부위 |
|---|---|
| 주 색상 | 모자 윗부분, 유니폼 상의 몸판, 양말 |
| 부 색상 | 모자 챙, 옷깃, 소매 끝, 등번호·표식 |
| 고정 요소 | 흰 바지, 검정 신발. 피부·머리색은 팀색과 별개 |
| 응원 도구 | 응원 수건·폼폼 등은 소속 팀의 주·부 색상 사용 |

- 주/부 색상 적용 부위는 현재 시안 적용안입니다. 공통 색상 선택과 양 팀 구별, 소속 인물의 같은 유니폼 사용은 확정 요구입니다.
- 봇은 사용자와 구별되는 색상을 배정합니다. 단순히 조합 이름만 다르게 만들지 않고, 선수의 몸판 등 주 색상이 비슷해 헷갈리는 조합도 피하는 방향입니다. 구체적인 유사 색 판별 수치는 F-2에서 정합니다.
- **우리 팀과 상대 팀의 치어리더 모두 해당 팀 선수와 같은 형태·배색의 유니폼을 입습니다.** 시안처럼 같은 상의·모자·바지·양말을 사용하고 표정·포즈·머리 모양·응원 도구로 역할을 구별합니다.
- **양 팀 관객 역시 소속 팀 선수의 유니폼·모자·표식을 공유**하고 응원 수건도 팀색을 따릅니다. 상대가 바뀌면 상대 선수·치어리더·관객이 같은 상대 설정으로 함께 바뀌어야 합니다.
- 중계진은 회색 계열 옷·헤드셋 등의 중립 배색을 쓰는 시안입니다.
- 초록+아이보리/H, 주황+남색/B는 구별을 보여주는 예시입니다. 특정 구단 로고나 이 두 조합만 선택하는 게임으로 정한 것이 아닙니다.
- 이 기본 유니폼 설정과 연동은 현재 범위입니다. 업적 등으로 얻는 특별 유니폼은 마지막 부록 K의 별도 확장입니다.

### H-4. 한 공의 흐름과 같은 그라운드의 사건 연출

선택 준비와 수비 이동 → B-5의 5초 입력/그대로 해 → 공을 놓음 → 타자 반응 → 타구·수비·주루 → 판정·기록·상태 반영 → 다음 공 또는 다음 타석.

- 사용자는 실제로 움직인 수비수를 보고 감독처럼 지시합니다. 원하는 위치로 지시해도 선수의 주력·야구센스·포구·송구와 상황에 따라 결과가 달라집니다.
- **본헤드는 기존 그라운드에서 실제 선수들이 실수하고 수습하는 움직임으로 표현**합니다. 별도 작은 영상창을 띄우거나 같은 사건을 다시 재생하는 방식으로 추가하지 않습니다.
- 사건을 이해시키기 위한 짧은 카메라 추적·확대는 검토 가능한 연출안입니다. 별도 장면 전환이나 모든 사건의 확대를 확정한 것은 아닙니다.
- 반응 말풍선은 사건의 결과를 바꾸거나 플레이를 다시 판정하는 장치가 아닙니다.
- 시안의 나눠진 칸과 화살표는 순서를 설명하는 도구이며 실제 게임에 여러 경기창을 동시에 띄우는 구성은 아닙니다.

### H-5. 본헤드 12종의 연출 방향

번호·관련 능력치·집계는 C-5를 유지합니다. 아래는 같은 경기 안에서 보여줄 행동의 흐름이며, 구체적인 동작 시간과 효과음은 미정입니다.

| 번호 | 화면에서 보여줄 흐름 |
|---|---|
| 1 | 타자가 타구를 감상하며 늦게 출발 → 공이 담장 안에 떨어짐 → 뒤늦게 전력질주 |
| 2 | 페어 타구를 파울로 착각해 멈춤 → 수비가 처리 → 뒤늦게 뛰거나 출루 기회를 잃음 |
| 3 | 공이 잡혔는데 주자가 계속 진루 → 원래 베이스로 송구 → 뒤늦은 귀루 시도. 실제 귀루 실패가 성립하면 병살 가능 |
| 4 | 주자가 베이스를 비껴 지나감 → 누락을 알아차리고 돌아감. 단순 누락 순간에 자동 아웃을 표시하지 않음 |
| 5 | 앞 주자가 멈춘 베이스로 뒤 주자가 접근 → 두 주자가 같은 곳에서 머뭇거림 → 수비의 태그와 후속 판정 |
| 6 | 공을 들고 지켜보는 포수와 주자 → 주자의 무모한 출발 → 포수의 송구와 주루 결과 |
| 7 | 아직 2아웃인데 공을 들고 더그아웃으로 걸음 → 상대 주자는 진루 → 뒤늦게 돌아봄 |
| 8 | 잡아야 할 주자가 있는 베이스를 두고 다른 베이스로 송구 → 기회를 놓치고 수습 |
| 9 | 태그가 필요한데 베이스만 밟고 공을 들고 있음 → 태그되지 않은 주자가 베이스에 닿아 살아남음 |
| 10 | 포구 성공에 기뻐하며 공을 들고 세리머니 → 필요한 송구 지연 → 상대 주자 추가 진루 |
| 11 | 두 수비수가 공을 향해 움직임 → 서로 양보하며 주춤 → 사이에 낙구 → 뒤늦은 회수·송구 |
| 12 | 공을 잡고 송구하려 함 → 받을 선수가 베이스에 없어 멈칫 → 상대 주자 진루와 수습 |

- 12종 모두 정지 시안 예시를 작성했습니다. 실제로 작동하는 12개 애니메이션이 완성됐다는 뜻은 아닙니다.
- 한 장면에 여러 선수가 실수해도 팀 본헤드 사건은 1회이며 개인 책임 기록은 A-3-1을 따릅니다.

### H-6. 일반 플레이의 움직임

| 사건 | 보여줄 핵심 동작 |
|---|---|
| 투구·스윙·타격 | 투수의 공 놓기, 타자의 실제 스윙/지켜보기, 배트와 공의 접촉 여부 |
| 헛스윙·루킹 삼진 | 빗나간 스윙 또는 지켜본 타자, 포수의 포구와 심판 판정 구별 |
| 땅볼 아웃 | 땅볼 처리→송구→베이스에서 먼저 포구. 필요한 강제 아웃 조건과 연결 |
| 플라이·직선타 아웃 | 높은 궤적 또는 빠른 직선 궤적→실제 포구 |
| 파울·볼넷·사구 | 파울 뒤 타석 재개, 볼넷 진루, 공식 사구 판정 후 진루를 각각 구분 |
| 안타·장타·득점 | 타구 낙하·회수와 각 주자의 상황별 진루. 모든 주자가 같은 칸 수만큼 이동하지 않음 |
| 병살 | 첫 아웃→송구/귀루 처리→두 번째 아웃. 실제 타순과 3아웃 한도 반영 |
| 도루 성공 | 주자가 태그보다 먼저 베이스에 닿음 |
| 도루 실패·도루 저지 | 포수 송구→공을 가진 글러브가 베이스 도달 전에 주자를 태그. 공격/수비 관점이 달라도 같은 사건 |
| 포구 실책·악송구 | 잡으려다 놓친 공 또는 빗나간 송구와 뒤늦은 수습 |
| 폭투·포일 | 잡기 어려운 투구와 잡을 수 있던 공을 놓친 상황을 구별하고, 포수가 뒤돌아 회수 |
| 희생플라이 | 포구·정상 귀루/태그업·후속 진루와 인정된 득점 |

- 일반 플레이는 공과 선수의 움직임, 짧은 판정 표시로 읽히게 합니다. 각 사건의 카메라 범위·효과음·길이는 F-2에서 다듬습니다.
- 플레이 움직임과 판정 표시는 화자 카드와 다른 요소입니다. 화자 카드를 하나만 띄우더라도 타구·아웃·득점 동작을 생략하는 뜻은 아닙니다.

### H-7. 홈런은 크게 축하

**사용자 요구:** 홈런은 일반 플레이보다 크게 축하합니다.

현재 우리 팀 홈런 시안의 순서:

1. 타구가 담장을 넘어가는 장면을 보여줍니다.
2. 그라운드 중앙에 큰 ‘홈런!’과 팀색 효과, 관중 환호·폭죽/색종이 효과를 보여줍니다.
3. 타자와 주자가 홈→1루→2루→3루→홈의 순서로 베이스를 돕니다.
4. 홈을 밟는 장면과 동료들의 환영으로 마무리합니다.

- 양옆 타순 등 기본 경기 정보를 유지하는 시안입니다. 정확한 확대 범위·길이·소리 크기는 미정입니다.
- 치어리더가 나오는 그림은 반응 후보 중 한 예입니다. 모든 홈런에 우리 치어리더를 추가로 고정 등장시키지 않고 I의 사건당 한 화자 규칙을 따릅니다.
- 끝내기 홈런은 홈런·역전·승리가 겹쳐도 반응 카드 하나를 쓰며, 경기 종료·득점·보상을 중복 반영하지 않습니다.
- 상대 홈런에도 실제 타구·베이스 순회·득점은 표현합니다. 상대 축하의 구체적인 강도와 효과 시간은 아직 따로 확정하지 않았습니다.

### H-8. 경기 밖 화면의 움직임 적용안

- 메뉴 이동은 짧게 전환하고, 성장 시 선택한 능력치의+1과 정확한 코인 차감이 보이게 강조합니다.
- 영입은 공개된 선수와 능력치를 보여준 뒤 영입/15코인 선택으로 이어집니다. 재접속이나 연출 재생으로 선수를 다시 뽑지 않습니다.
- 결과에서는 승패·점수·기록·정확한 코인/트로피 보상을 읽을 수 있게 보여줍니다.
- 별도 선수 레벨·경험치 체계, 유료 영입 버튼 등 참고 이미지에만 있던 게임 규칙을 가져오지 않습니다.
- 전환 시간·능력치 강조·등장 효과는 검토용 연출안입니다. 정확한 시간 수치나 구현 완료를 주장하지 않습니다.

## 부록 I. 사건 반응과 상황별 무작위 멘트

### I-1. 화자와 말투 — 방향 확정

| 화자 | 말투와 외형 방향 |
|---|---|
| 중계진 | 담담한 사실 설명 뒤 짧은 지적. 회색 옷·헤드셋의 중립 배색 시안 |
| 우리 팀 치어리더 | 응원 속에 핀잔을 섞고 좋은 플레이에는 크게 축하. 우리 선수와 같은 유니폼 |
| 상대 팀 치어리더 | 밝고 예의 바른 말투의 도발. 상대 선수와 같은 유니폼 |
| 상대 팀 관객 | 직설적이고 편파적인 놀림. 상대 선수와 같은 유니폼·응원 도구 |
| 우리 팀 관객 | 화내면서도 계속 보는 애증, 성공에는 큰 환호. 우리 선수와 같은 유니폼·응원 도구 |

- **반응 대상 사건 하나당 위 화자 카드 중 하나만 등장**합니다. 중계진 카드에 해설과 캐스터가 함께 그려져도 별도 사건 반응 두 개를 띄우는 것으로 처리하지 않습니다.
- 위치는 그라운드 내부 오른쪽 상단입니다. 등장 약 0.25초→대사 약 3초→퇴장 약 0.25초의 방향으로 미끄러져 들어오고 나갑니다.
- 주요 경기 동작, 타순·타자/투수 정보, 선택 시간을 가리지 않게 배치합니다. 실제 읽는 시간과 다른 사건의 반응이 겹칠 때의 처리는 F-2에서 조정합니다.

### I-2. 현재 후보 선택과 중복 방지

**현재 요구:** 상황별 3~4개의 멘트를 무작위로 사용합니다. 현재 작성한 목록은 모든 상황에 4개씩이며, 각 후보는 ‘화자+멘트’ 한 쌍입니다. 선택된 후보의 화자만 표시합니다.

- **현재 작성량:** 일반 상황 30개 + 본헤드 12종 = 42상황, 총 168개. I-3에 전체 후보를 통합합니다.
- 전체 말투 방향과 사건당 한 반응·상황별 무작위 선택은 사용자 결정입니다. 아래 개별 문구는 검토용 후보이며 최종 선별·세부 가중치는 남아 있습니다.
- **선택 적용안:** 한 사건에서 가장 구체적으로 맞는 상황 묶음 하나를 고른 뒤 그 묶음의 후보 하나를 무작위로 선택합니다.
- 본헤드로 아웃되면 해당 본헤드 후보를 사용하고 일반 아웃 멘트를 이어서 띄우지 않습니다. 끝내기 홈런에는 끝내기 홈런 후보 하나를 사용하고 일반 홈런·역전·승리 반응을 겹치지 않습니다.
- 도루 실패와 상대 수비의 도루 저지는 같은 사건입니다. 타석 결과와 연속 무안타 갱신도 같은 사건의 복수 반응으로 만들지 않습니다.
- 일반 안타로 역전하면 역전 후보 등 더 구체적인 후보를 우선하는 적용안입니다. 결과 화면으로 넘어갔다는 이유만으로 같은 경기 종료 사건의 반응을 다시 뽑지 않습니다.
- **반복 억제 제안:** 같은 상황에서 직전 문구를 제외하고 남은 3개 중 무작위로 고릅니다. 최초 선택은 4개에서 고릅니다. 이 방식의 채택과 화자별 확률은 아직 확정하지 않았습니다.
- {N}은 실제 연속 무안타 타수이며 6이상에서만 사용합니다. 볼넷·사구 등으로 늘리지 않고 안타 후 해제합니다. 별도 반응과 겹치지 않는 사용 시점은 A-3-4·F-2를 따릅니다.
- 홈런·득점·승패·무승부는 판정 확정 후, 본헤드는 실수 행동이 드러난 뒤 반응합니다. 말풍선이 미래 결과를 확정하거나 경기 판정을 바꾸지 않습니다.
- **상황별·화자별로 3~4개씩 추가하는 확대는 현재 168개와 구분하여 마지막 부록 K에 둡니다.** 이번 통합 작업에서 추가 확장 문구를 만들거나 표시 기능을 구현하지 않습니다.

## 부록 K. 추후 여유가 생기면 추가할 기능

이 부분은 대화에서 사용자가 나중에 추가할 생각이라고 말씀하신 기능을 모은 것입니다. **현재 게임의 필수 완성 조건과 구분하며, 개발 순서·일정은 아직 정하지 않았습니다.** 현재 필요한 확률·화면·연출의 세부 설계는 F-2를 따릅니다.

### K-1. 상황별·화자별 멘트 3~4개 추가

- **최신 사용자 요청:** 후에 여유가 생기면 각 상황에 대해 **화자마다 멘트 3~4개씩을 추가**합니다.
- 대상 화자는 중계진, 우리 팀 치어리더, 상대 팀 치어리더, 상대 팀 관객, 우리 팀 관객의 다섯 역할입니다. 같은 사건도 각자의 응원 방향과 말투로 다르게 반응하도록 문구를 늘립니다.
- 현재 I-3의 목록은 **한 상황에 화자와 멘트가 짝지어진 후보 총 4개**입니다. 각 상황에 다섯 화자가 모두 3~4개씩 갖춰져 있다는 뜻이 아닙니다. 이번 v05에서는 기존 42개 상황·168개 후보를 통합하고, 이 추가 집필은 미래 작업으로 남깁니다.
- 멘트가 늘어나도 **사건 하나당 화자 카드 하나만 등장**하는 규칙은 유지합니다. 같은 사건에 다섯 화자가 차례로 모두 등장하지 않습니다.
- 실제 추가 시에는 상황 조건·응원 팀·기록에 맞는 문구를 작성하고, 화자 선택과 문구 선택의 확률·반복 억제를 함께 정합니다. 연속 무안타 멘트는 계속 6타수 이상에서만 사용합니다.

### K-2. 성장한 선수의 MLB 진출·판매

- 일정 수준까지 성장한 선수를 MLB에 보낼 수 있게 하는 방향입니다. 사용자가 처음 말한 판매 아이디어도 이 확장 안에서 검토합니다.
- 선수가 진출하면 현재 선수단에서 빠지고, 사용자는 잘 키워 보냈다는 뿌듯함을 느끼며 다른 선수를 영입·육성하는 흐름을 만들고자 합니다.
- 장기적으로 모든 능력치가 100인 선수가 쌓이는 상황에 대비하는 아이디어입니다. **현재 작은 프로젝트의 필수 기능으로 넣거나 강제 이적·은퇴 규칙을 추가하지 않습니다.**
- 진출 능력치 조건, 사용자의 선택 방식과 시점, 판매 대가 유무·금액, 진출 선수의 기록 보존 방식은 미정입니다.
- 진출 후에도 출전 가능한 선수 9명을 어떻게 유지할지, 새 선수 육성과 높아진 상대 난이도를 어떻게 맞출지도 이 기능을 개발할 때 정합니다.
- 이전에 제안된 **‘후임 랜덤 선수 지급’과 ‘진출 선수 명단’은 아직 확정하지 않은 아이디어**입니다. 자동으로 지급하거나 별도 명단 화면을 반드시 만드는 요구로 해석하지 않습니다.

### K-3. MLB 진출 인원에 따른 업적과 보상

- MLB에 보낸 선수 수에 따라 업적을 달성하게 하는 방향입니다.
- 업적 보상은 트로피 또는 코인을 주는 방향을 검토합니다. 몇 명마다 어떤 보상을 얼마나 줄지는 아직 정하지 않았습니다.
- 현재는 경기 승리당 트로피 +1이고, 상대 난이도는 누적 5승마다 올라갑니다. **향후 업적에서도 트로피를 지급한다면 누적 승리 수와 트로피 보유 수를 구분**해야 합니다. 업적 트로피를 경기 승리로 잘못 세어 상대 난이도가 올라가지 않도록 그때 저장·표시 기준을 함께 정합니다.

### K-4. 팀 칭호

- 게임을 더 확장할 수 있을 때 팀 칭호를 추가합니다.
- 팀을 키운 성과를 드러내는 요소로 검토하며, 종류·획득 조건·표시 위치·능력치 효과 유무는 미정입니다.

### K-5. 특별 유니폼

- 향후 업그레이드에서 특별 유니폼을 추가할 수 있습니다.
- 디자인, 획득 조건, 선택 화면과 보유 방식은 아직 정하지 않았습니다.
- **현재 H-3의 주·부 색상 선택과 선수·치어리더·관객의 유니폼 연동은 이미 현재 범위**입니다. 특별 유니폼을 나중에 넣는다는 이유로 기본 배색 기능을 미루지 않습니다.

### K-6. 사용자가 직접 내리는 주루 지시

- 추가 개발 기회가 생기면 사용자가 주자에게 직접 지시하는 기능을 검토합니다.
- 현재 추가 진루·도루는 선수가 주력과 경기 상황, 상대 수비·송구 등을 보고 자동으로 판단합니다.
- 직접 지시의 종류, 입력할 수 있는 시점, 주자 선택 방법, 확정·변경·취소 규칙은 아직 정하지 않았습니다. 현재 공격·수비 입력 규칙만으로 미래 주루 조작까지 확정하지 않습니다.

### K-7. 휴대폰에 맞춘 화면과 조작

- 우선 PC 중심으로 완성한 뒤, 휴대폰 화면 크기와 터치에 맞게 배치·글자·버튼·경기 정보 표시를 조정합니다.
- 양옆 타순, 현재 선수 정보, 수비 지시, 5초 표시와 반응 카드가 작은 화면에서 어떻게 함께 보일지는 별도 설계합니다.
- PC와 휴대폰의 계정 공유나 자동 저장 동기화를 약속한 것은 아닙니다. 현재는 브라우저 안의 독립된 저장칸 2개를 사용하며, 기기 간 자동 동기화는 범위에 포함하지 않습니다.

위 항목은 추가 개발 여유가 생겼을 때 다시 구체화할 계획입니다. 현재 제외한 구단 시설·팬 관리·스폰서·연봉 등은 이 목록에 자동으로 포함하지 않습니다.
