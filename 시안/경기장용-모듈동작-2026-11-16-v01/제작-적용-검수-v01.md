# 경기장용 캐릭터 · 제작과 적용 기준

2026-11-16 · 시안 제작 및 로컬 실제 경기 자체 검수. 공개 사이트 버전16 검수는 [별도 결과](공개사이트-v16-검수-v02.json)에 기록했습니다. 사용자의 최종 미술 승인을 대신하는 기록이 아닙니다.

## 사용할 자산

선수창은 상세 도트 초상, 경기장은 단순 도트입니다. 같은 선수의 기존 `appearance`를 두 렌더러에서 공유합니다. 저장된 체형 번호·머리·피부·눈·장비 선택을 바꾸지 않습니다.

| 묶음 | 현재 사용 |
| --- | --- |
| 6체형 | 작은형, 키큰형, 보통형, 어깨형, 날렵형, 중량형. 머리 크기는 공통, 몸의 키·굵기는 기존 비례 유지 |
| 몸 | 체형마다 기본36·마무리3·달리기8·타격3폼12·개인 버릇18 =77자세. 총462몸 |
| 머리 | 기존 보통형 정면 빈 머리 + 사선/뒤 방향. 몸과 분리하여 목에 연결 |
| 얼굴 | 정면/사선 눈6종, 눈썹·코·입 각6종. 뒤 방향에는 이목구비 없음 |
| 머리/장비 | 머리카락7종4방향, 모자·헬멧4방향, 안경·선글라스·안대·수염·눈 밑 표식 |
| 경기 장비 | 배트는 손잡이가 포함된 몸 그림. 글러브·포수 마스크·보호대는 별도8종v02 |
| 색 | 피부6, 눈동자6, 머리색7 및 구단 주색/보조색. 얼굴과 목·팔·손의 피부 팔레트 공통 |

원본 PNG, 생성 요청문, `에셋-배치자료-v01.json`을 함께 보관합니다. 잘못 나온 칸과 앞 버전은 비교 자료이며 자동으로 삭제하지 않습니다. 경기에서는 몸의 연결 영역을 고르고 최근접 축소·불투명 정수 도트로 합성합니다. 맨머리·장비 없음도 정상 조합입니다. 안대와 안경/선글라스는 함께 표시하지 않습니다.

## 연결하는 동작

[34장면 비교](flows.html)에서 6체형·서로 다른3선수·좌우 타석을 바꿔 볼 수 있습니다. 기본 동작을 재사용하며, 상황마다 새 그림을 한 벌씩 늘리지 않습니다.

| 상황 | 선택·재사용하는 자세 |
| --- | --- |
| 입장 | 홈 오른쪽/원정 왼쪽 걷기 → 감속 → 몸풀기 → 타격 준비. 좌우 타자석과 출발 쪽은 독립 |
| 타격 | 어깨 높이/다리 들기/낮게 모으기3폼, 준비·힘 모으기·맞힘·마무리 각4칸 → 배트 정리·첫발 |
| 타석 유지 | 공 지켜보기, 체크 스윙, 헛스윙 균형 회복, 파울 확인 → 준비 복귀 |
| 볼넷·사구 | 배트 정리/몸 추스르기 → 걷기 → 1루 접촉 |
| 주루 | 새8칸의 균형 보폭/빠른 발 교대2리듬. 두 번째는 별도8장 신작이 아닌 재생 리듬 선택 |
| 베이스 | 감속 → 발 접촉 → 대기. 연속 진루는 베이스를 통과하는 곡선으로 몸 방향 전환 |
| 슬라이딩 | 발 먼저3칸/머리 먼저3칸. 세이프 후 손·발 접촉을 유지하며 일어나기 |
| 리드·귀루 | 베이스에서 나오기, 리드 유지, 귀루와 재접촉, 태그업, 오버슬라이드·재접촉 |
| 아웃 | 루킹/헛스윙 삼진, 뜬공 확인, 포스/태그 아웃 → 고개·몸 반응 → 벤치 쪽 걷기 |
| 득점 | 홈 터치 후 짧은 안도. 홈런은 타격 직후 확인·순회·홈 이후 버릇/세리머니를 나눔 |
| 실수 | 타구 구경/파울 착각/포구 후 계속 뛰기/베이스 누락/두 주자 충돌/무리한 도루/아웃 수 착각과 수습 |
| 교대 | 벤치 쪽 퇴장과 새 수비 위치 입장. 기존 공수 교대 사건에 연결 |

입장 연출은 타석당1.8초를 기본으로 정했습니다. 반복 타석·대타도 같은 짧은 길이를 사용하고 자동 배속을 따릅니다. 추가 루틴은6개 버릇의3단계를 재사용합니다. 성격 하나가 타격폼·달리기폼을 독점하지 않습니다. 선수 ID와 저장된 `visualForm`으로 선택을 유지하며 능력치와 경기 판정은 바꾸지 않습니다.

## 실제 게임 연결과 기준점

- `player-motion-v13.js`: 개인 폼과34장면의 표현. 독립 비교에서 전체 흐름을 확인합니다.
- `field-renderer-v13.js`: 64×64 내부 칸, 목 위치, 공통 머리, 피부·옷 색, 실제 불투명 손/발 접촉점.
- `field-integration-v13.js`: 기존 경기 사건의 타격·달리기·슬라이딩·아웃·환호를 새 자세로 표시. 글러브는 몸의 손 색 영역, 배트는 원래 몸 프레임에 붙어 있어 손잡이가 따로 떠다니지 않습니다.
- `stadium-view-v13.js`: 공격 준비는 포수 뒤 낮은 구도, 타구/주루 및 수비는 넓은 구도. 첫/셋째 베이스와 투수판 좌표를 실제 표시 위치에 맞춤. 선수 입장 마지막 위치 튐 보정.
- 세이프/아웃은 기존 엔진의 결과를 따릅니다. 공이 먼저 왔다는 이유만으로 새 아웃 판정을 만들지 않습니다. 태그와 포스 아웃을 구별하고, 세이프 주자는 접촉점을 베이스에 유지합니다.
- 독립 비교의 체크 스윙·리드·오버슬라이드 등은 표현 시안입니다. 기존 엔진에 없는 사건을 이번 미술 작업에서 새 규칙으로 발생시키지 않습니다. 해당 사건이 발생하는 흐름과 기본 반응만 실제 게임에서 연결합니다.

## 화면과 현수막

전광판에 두 팀 점수와 현재 공격 타순9명을 넣었습니다. 타자/투수 얼굴·정보, 이닝·BSO·주자, 지시, 교체, 소리, 배속, 자동/반자동, 일시정지, 작은 경기 기록과 심판4명을 유지합니다. 결과 알림은 하단 중앙 기록 영역에 표시해 얼굴 카드를 덮지 않습니다. 기존9개 수비 배치 선택을 유지합니다.

`stadium-banners-v13.js`의 `catalog`에 문구를 추가합니다. 고유번호는 재사용하지 않고, 단계·천 종류·사용 여부를 지정합니다. 기존 문구 배열 끝에 새 객체를 추가하면 이미지 생성이 필요 없습니다. 빈 천은 짧은형/넓은형 도트 도형을 재사용합니다.

```js
StadiumBannersV13.catalog.push({
  id: 'banner-new-001', text: '우리 팀 끝까지 응원!',
  stage: 0, cloth: 'wide', enabled: true
});
```

새 경기에는 평온2/술렁임2/분노4/해체 직전6개를 중복 없이 고릅니다. 원정은 우리 팬 구역의 최대3개, 응원 관객0이면0개입니다. 부족한 후보는 중복으로 채우지 않습니다. 문구·자리·당시 단계를 경기와 완료 기록에 저장합니다. 목록 변경은 다음 경기부터 적용합니다.

글자는900px 기준11px로 실제 폭을 재고 최대2줄로 나눕니다. 짧은 천에 안 맞으면 넓게 표시하며, 넓은 천에도 들어가지 않는 긴 문구는 표시 후보에서 제외하고 짧게 다듬습니다. 문장을 잘라 붙이거나 끝없이 축소하지 않습니다. 같은 관중석 난간의6개 자리를 두 카메라에서 공유합니다.

실제 속도·정지 확대·배경이 다른 화면을 함께 확인했습니다. 숫자 검사는 그림의 취향이나 모든 가능한 파츠 조합의 무결함을 보장하지 않습니다. 선택한 조합·장면을 근거로 수정했으며, 이전 실패 자료는 이름에 버전을 남겨 구별합니다.

최종 공개 화면은 [공격v02](공개사이트-v16-공격화면-v02.png)와 [수비v03](공개사이트-v16-수비화면-v03.png)입니다. 초기 캡처의 경기 시작 안내창을 닫고 다시 저장했습니다. 공수만 강제 변경한 초기 검사 데이터에 이전 팀 주자가 남아 발생한 오류는 잘못된 검사 데이터로 재현했습니다. 전체 자산을 읽은 새 격리 구단에서 정상 투구 재생과 두 화면을 재검수한 결과는 공개 검수v02에 기록했습니다. 실제 저장 데이터는 검사 전후 동일했습니다.
