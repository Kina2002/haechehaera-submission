## 단계별 기록

### 1. ZIP과 로컬 폴더 (2026-09\~10-07)

**무엇이 바뀌었나**

- 수업 자료를 ZIP으로 받아 로컬 실습 폴더에서 작업했습니다.
- 기획서는 v01\~v07, 게임은 v01\~v27처럼 버전마다 새 파일로 남겼습니다([개발 기록 정리](../../기획참고/해체해라-개발기록-2026-11-09-v01.md)).
- 진행 상황은 수업 실습 폴더 맨 위 `작업일지.md` 한 파일에 이어 적었습니다. 요청한 목표·한 일·결과 경로·참가자가 확인한 내용·다음 할 일을 남기고, 확인하지 않은 것은 "참가자 확인: 아직 없음"으로 적습니다.
- 2026-10-07 새 프로젝트로 넘기려고 이어가기 폴더와 ZIP을 만들었습니다(구현명세, v27 게임, 개발 원본, 이전 기획서, 검증 자료, 먼저읽기).
- 같은 날 이 폴더에서 새 구현본을 만들 때도 Git 저장소가 아니었습니다. 작업일지에 "가지·커밋·PR을 만들지 않음"으로 적었습니다.

**왜**

- 수업 자료가 ZIP 방식이었습니다. Git과 GitHub는 2026-09-15부터 수업 연습 저장소에서 익혔습니다.

**실수·고칠 점**

- 기록에 없음.

**다음엔 이렇게**

- 새 프로젝트는 처음부터 Git 저장소로 시작합니다. 파일 이름에 버전을 붙이는 대신 Git이 이력을 보관합니다.

### 2. GitHub 저장소와 Codex의 PR (2026-10-07\~10-13)

**무엇이 바뀌었나**

- 2026-10-07 공개 저장소를 만들고 이어가기 폴더 전체를 올렸습니다. 269개 파일, 약 251.83MiB, 첫 커밋 38df27b입니다.
- `.gitattributes`로 모든 파일을 바이트 그대로 보존하게 했습니다. 줄 끝 형식(줄이 끝났다는 보이지 않는 표시, CRLF·LF)도 바꾸지 않습니다.
- Codex는 기능마다 `codex/…` 가지를 만들고 PR을 열었습니다(PR #1\~#34).
- 공개 사이트 배포는 GitHub에 합치는 일과 따로 했습니다([DEPLOYMENT.md](../../DEPLOYMENT.md)).

**왜**

- 참가자가 제출 저장소를 만들고 폴더 전부를 올리라고 요청했고, 공개를 골랐습니다.
- 수업 규칙(AGENTS.md)은 "기능마다 별도 가지 → 검증 → 커밋·푸시 → PR에서 확인"입니다.

**실수·고칠 점**

- PR #2\~#10은 main이 아니라 앞 PR의 가지 위에 쌓였고, 합치지 않은 채 남았습니다. 그래서 main에는 최신본이 보이지 않았습니다. 2026-10-08 참가자가 "최신본이 GitHub에서 바로 보이게"를 요청한 뒤, 대상 가지를 main으로 바꿔 #1\~#10을 순서대로 합쳤습니다. 같은 날 #12\~#14도 가지에 남아 있어 따로 합쳤습니다.
- [DEPLOYMENT.md](../../DEPLOYMENT.md)는 2026-10-13 새 주소로 옮긴 뒤에도 예전 주소와 업적 15개를 적고 있다가 2026-11-10에 고쳤습니다(커밋 4f874be).

**다음엔 이렇게**

- PR은 main을 기준으로 만들고, 확인이 끝나면 미루지 않고 합칩니다. 열린 PR이 쌓이면 main이 최신이 아닙니다.

### 3. Claude 합류와 "병합해 줘" (2026-11-05)

**무엇이 바뀌었나**

- Claude가 게임 규칙 수정을 맡았습니다. 고칠 것 하나마다 `claude/주제-20261105` 가지와 PR을 만들었습니다(PR #35\~#42).
- 참가자가 "병합해 줘"라고 한 뒤에 합쳤습니다.
- 작업일지 제목에 어디까지 했는지 적었습니다. 예: "(PR까지, 배포 없음)", "PR 병합 (배포 없음)". 사이트 배포는 별도 요청으로 했습니다.
- 이날 Claude가 만든 시안(승부처 개입, 원근감 개선)은 커밋하지 않고 로컬에만 두었습니다. 2026-11-09 참가자가 "Codex와 이어서 작업하려고" 캐릭터 리디자인 시안까지 3개를 올려 달라고 해 PR #43으로 올렸습니다.

**왜**

- 참가자가 고칠 순서를 고르고, 하나씩 고친 뒤 PR에서 확인하는 방식이었습니다.

**실수·고칠 점**

- 줄 끝 형식이 섞인 파일을 고칠 때 형식을 지키려고 바이트 단위로 수정해야 했습니다(작업일지 2026-11-05 "막혔던 것").

**다음엔 이렇게**

- PR 하나에 고칠 것 하나를 담습니다. "PR까지 / 합침 / 배포"처럼 어디까지 했는지 기록에 적습니다.

### 4. 두 AI 동시 작업과 이슈 #46 (2026-11-09)

**무엇이 바뀌었나**

- 역할을 나눴습니다. Codex는 디자인, Claude는 시스템·재화·능력치 기획을 맡았습니다.
- Codex가 원래 폴더(main)에서 시안을 만드는 동안, Claude는 그 폴더의 가지를 바꾸지 않았습니다. worktree를 따로 만들어 `claude/season-economy-20261109` 가지에 그날 파일 19개만 커밋했습니다(PR #45). Codex도 디자인 기록을 별도 worktree의 `codex/design-record-20261109` 가지로 올렸습니다(PR #47).
- Claude는 합치기 전에 Codex PR #47과 충돌하는지 모의 병합(실제로 합치지 않고 미리 합쳐 보는 검사)으로 확인했습니다. #47은 "Codex 작업이라" 합치지 않았습니다.
- 퇴근 11분 전, 참가자가 집에서 이어 할 수 있게 GitHub에만 정리해 달라고 했습니다. [이슈 #46](https://github.com/Kina2002/haechehaera-submission/issues/46)에 그날 정한 것·시험 결과·다음 할 일 8개·이어하기 안내를 적었습니다. 안내에는 AI에게 할 말까지 넣었습니다: "GitHub 이슈(이 이슈)와 PR #45를 읽고 다음 할 일 1번부터 이어서 하자".
- PR #45는 참가자가 "응, 합쳐 줘"라고 한 뒤, PR의 마지막 커밋(edd6edc)이 확인한 것과 같은지 보고 합쳤습니다.

**왜**

- 같은 폴더에서 가지를 바꾸면 다른 AI의 작업을 건드립니다.
- 작업일지는 저장소 밖에 있어 GitHub에 올라가지 않습니다. 집에서 이어 하려면 GitHub에 남겨야 했습니다.

**실수·고칠 점**

- 원래 폴더에도 같은 문서가 커밋되지 않은 채 남았습니다. PR을 합친 뒤 그 폴더에서 main을 받으면 같은 이름의 파일 때문에 막힐 수 있습니다. 2026-11-11 기준으로도 원래 폴더의 main은 ede421a(2026-11-09)에 머물러 있고, P09\~P15와 시뮬레이터, Codex 시안 폴더가 커밋 안 된 채 남아 있습니다.
- 편집 도구가 F 문서의 줄 끝 형식을 바꿔 바뀐 줄이 크게 늘었습니다. 자세한 내용은 [명세 변경 기록](../03-기능-명세/명세-변경기록.md) 5단계에 있습니다.

**다음엔 이렇게**

- 다른 AI가 쓰는 폴더에서는 작업하지 않고, 처음부터 worktree에서 시작합니다.
- 하루를 마칠 때 다음 할 일과 "AI에게 할 말"을 이슈에 남깁니다.

### 5. 할 일 하나에 PR 하나 (2026-11-10)

**무엇이 바뀌었나**

- 회사 폴더에 복사본이 또 남지 않게, 처음부터 worktree에서 새 가지로 시작했습니다. 합친 뒤에는 임시 작업 폴더를 정리했습니다.
- 이슈 #46의 할 일 하나마다 PR 하나를 만들었습니다(PR #48\~#53). 합치면 이슈 항목에 체크하고 PR 번호와 날짜를 적었습니다. 할 일은 기준일까지 8개에서 14개로 늘었습니다.
- 커밋 메시지에 `Refs #46`을 붙여 이슈와 연결했습니다.
- 합칠 때마다 Codex PR #47이 새 main과 충돌하지 않는지 확인했습니다. Codex도 PR #47에 커밋을 더할 때 Claude의 기획 변경을 넣지 않았습니다.
- PR 설명은 참가자가 읽을 수 있게 쉬운 말로 썼습니다. 요약·결정·시험 결과·바뀐 파일·확인한 것·아직 안 된 것으로 나눴고, 확인한 것에는 링크 검사 결과를 적었습니다(예: PR #51 "문서 링크 383개, 깨진 링크 0 · 고친 문서의 줄 끝 형식 유지").
- 시뮬레이션은 원자료 JSON과 실행 명령(`node tests/run-economy-sim.cjs …`)을 P 문서에 함께 남겼습니다. 참가자 확인용으로만 돌린 시험(수입원·지출원)은 가지를 올리지 않고 지웠습니다.
- 저녁에 Codex PR #54(나이·노화)와 #47이 합쳐졌고, Claude가 문서를 맞췄습니다(커밋 9ccbbf3).

**왜**

- 남은 일은 이슈 하나에서 보고, 변경은 PR로 하나씩 확인하려고 했습니다.

**실수·고칠 점**

- 아침에 "어제 집 작업"을 찾았지만 GitHub에는 전날 16:49 이후 변경이 없었습니다. 집 컴퓨터에만 있는 작업은 보이지 않았습니다. 그래서 나이 규칙이 올라오기 전까지 Claude는 임시 가정으로 시험했고, 저녁에 PR #54가 합쳐진 뒤 다시 시험했습니다.

**다음엔 이렇게**

- 컴퓨터를 옮기기 전에 가지를 GitHub에 올립니다. 합치지 않아도 올려 두면 다른 곳에서 볼 수 있습니다.

### 6. 여러 컴퓨터·여러 세션 (2026-11-11)

**무엇이 바뀌었나**

- 집 노트북에서 한 작업(PR #54\~#59 등)이 이미 main에 들어와 있었습니다(작업일지 2026-11-11). 이 작업의 기록은 회사 컴퓨터 작업일지에 없고, PR과 이슈로 확인했습니다.
- Claude 쪽 브라우저의 GitHub 로그인이 풀려, 3건을 PR 없이 main에 바로 합쳤습니다. P24 해결 방안(f6be940), MLB 진출 보상 시험(b12084d), 임시 안내 페이지(240cc31)입니다.
- 다른 컴퓨터(부트캠프 노트북 등)에서 이어 보려고 [지금-먼저-볼-것.md](../../지금-먼저-볼-것.md)를 만들었습니다. 참가자가 정할 것, 그날 한 일, 지금까지 정한 것, 파일 위치를 한 장에 모았습니다. 저장소 첫 화면 README 맨 위에 안내 줄을 달았고, 확인이 끝나면 지워도 되는 임시 페이지입니다.
- MLB 진출 보상 시험 v03의 원자료(26개, 약 33MB)는 저장소에 넣지 않았습니다. 요약 JSON과 실행·집계 명령만 남겼고, 같은 명령으로 똑같이 다시 만들 수 있습니다. 보상을 켜지 않으면 P23 원자료와 숫자 하나까지 같아서, 같은 구단끼리 비교할 수 있습니다([P15](../../구현/해체해라-2026-10-07-v01/문서/SPEC-기능별-2026-10-07-v01/P15-MLB-출신-후원과-구단-회생권.md)). v04·v05(PR #61)도 요약만 올렸습니다.
- PR #61(MLB 진출 보상 결정, P24 참가자 답, P27)은 기준일에 열려 있습니다.

**왜**

- PR 없이 합친 이유는 로그인 만료입니다(지금-먼저-볼-것.md "참고").
- 원자료가 커서 저장소에 넣지 않았습니다. Codex도 2026-11-09 약 100MB 단일 실행 파일을 올리지 않고 다시 만드는 방법만 남겼습니다.

## 지금 방식 (2026-11-11)

1. **시작:** GitHub의 최신 main을 확인하고, worktree와 새 가지(`claude/…`, `codex/…`)를 만듭니다.
2. **작업:** 결정은 P 문서에, 시험은 시뮬레이터로 합니다. 큰 원자료는 올리지 않고 요약과 명령을 남깁니다.
3. **확인:** 링크 검사(깨진 링크 0)와 줄 끝 형식 유지를 확인합니다.
4. **PR:** 쉬운 말로 설명하고, 이슈 #46과 연결합니다(`Refs #46`).
5. **합치기:** 참가자가 "합쳐 줘"라고 한 뒤에만 합칩니다. PR의 마지막 커밋과 다른 AI의 PR 충돌을 확인합니다. 작업일지에 합친 과정이 남은 PR(#35\~#43, #45, #48\~#53)은 모두 참가자 요청 뒤에 합쳤습니다. 다른 AI의 PR은 합치지 않습니다.
6. **기록:** 작업일지(이 컴퓨터), 이슈 #46(모든 컴퓨터), 지금-먼저-볼-것.md(임시)에 남깁니다.

## 돌아보며

- 컴퓨터나 AI를 바꾸기 전에 작업을 GitHub에 올립니다. 올리지 않은 작업은 다른 곳에서 보이지 않습니다.
- AI마다, 할 일마다 가지와 작업 폴더(worktree)를 따로 씁니다. 같은 폴더에서 두 AI가 동시에 작업하지 않습니다.
- 합치기는 사람이 "합쳐 줘"라고 말한 뒤에만 합니다. PR마다 누가 합칠지 정해 둡니다.
- 열린 PR을 오래 쌓아 두지 않습니다. 쌓이면 main이 최신이 아닙니다.
- 할 일 목록은 한 곳(이슈)에 둡니다. 안내 페이지와 작업일지는 그곳을 가리킵니다.
- 큰 결과 파일은 올리지 않고, 요약과 다시 만드는 명령을 남깁니다.
