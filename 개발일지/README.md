## 가장 크게 배운 것

1. **먼저 만들어 보고 고치는 것이 빨랐습니다.** 기획서의 미정 항목이 많아도 게임을 시험값으로 먼저 만들고, 플레이 피드백으로 기획서와 숫자를 고쳤습니다([01](01-기획/기획서-변경기록.md) · [02](02-게임-버전/게임-버전-변경기록.md)).
2. **"정해진 것"과 "정한 과정"은 다른 문서에 둡니다.** 지금 게임 설명(F), 앞으로의 기획(P), 시험 기록(이 개발일지)을 나누자 문서가 짧고 읽기 쉬워졌습니다([03](03-기능-명세/명세-변경기록.md) · [04](04-시스템-밸런스/README.md)).
3. **시뮬레이션 결과는 가상 감독의 행동에 크게 좌우됩니다.** 결과가 이상하면 규칙보다 감독 설정부터 확인하고, 임시 가정은 임시라고 밝힙니다([04](04-시스템-밸런스/README.md)).
4. **작은 버전을 빨리 만들고, 요청 하나씩 반영합니다.** 화면 시안은 하루에 v01\~v04, 사운드는 v01\~v09를 만들며 고쳤고, 결정은 따로 적었습니다([05](05-디자인/디자인-변경기록.md) · [06](06-사운드/사운드-변경기록.md)).
5. **사람이 고르고, 숫자 검사는 돕기만 합니다.** 소리는 자동 검사 뒤 참가자가 듣고 골랐고, 시스템 숫자도 결과 표를 보고 참가자가 정했습니다([06](06-사운드/사운드-변경기록.md) · [04](04-시스템-밸런스/README.md)).
6. **작업은 가지·PR로 나누고, 할 일은 한 곳에 둡니다.** 다른 컴퓨터나 AI로 넘기기 전에 GitHub에 올리고, 합치기는 사람이 확인한 뒤에 합니다([07](07-협업-작업방식/협업-변경기록.md)).
